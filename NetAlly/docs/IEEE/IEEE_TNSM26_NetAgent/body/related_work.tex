\section{Related Work}

\subsection{Network LLM Benchmarks}

\textbf{Knowledge-based QA.}
These benchmarks evaluate how accurately an LLM can reproduce content from standard documents.
TeleQnA~\cite{ref9} evaluates telecommunications domain knowledge using multiple-choice questions extracted from 3GPP documents, while TeleQuAD~\cite{ref10} measures reading comprehension through span extraction from the same documents.
NetBench~\cite{ref11} uses expert panels to evaluate LLM responses to expert-curated descriptive questions.
While these benchmarks are useful for verifying the domain knowledge of LLMs, they do not evaluate the ability to reason about operational behavior within specific network topologies.

\textbf{Configuration Generation.}
This category assesses whether an LLM can generate correct configuration files.
NetConfEval~\cite{wang2024netconfeval} requires LLMs to generate router configurations from given requirements and uses Batfish to verify syntactic and semantic correctness.
NetComplete~\cite{ref28} proposes a synthesis approach that automatically completes partial configurations based on SMT.
NETLLM\allowbreak BENCH~\cite{ref12} combines YANG schema-based configuration generation with emulation-based verification.
In contrast, while this line of research evaluates the ability to \emph{write} configurations, this paper focuses on the ability to \emph{read and reason} about existing configurations.

\textbf{Dynamic Reasoning.}
This category, including our work, evaluates the ability to infer the runtime behavior of a network.
NetPress~\cite{ref7} evaluates LLM performance by generating network states at runtime and requiring the model to predict protocol behavior, measuring both accuracy and safety.
NetConfigQA~\cite{ref26}, a predecessor to this work, introduced a configuration interpretation QA task on a single topology but lacked a hierarchy of difficulty levels and simulation-based questions.
NetConfigQA~2.0, proposed in this paper, extends the original NetConfigQA by providing a five-level cognitive difficulty framework based on real configuration files, an automated QA generation pipeline across four topologies, and TA-Acc, an evaluation metric specialized for network data.

\subsection{LLM-based Network Management Agents}

Research applying LLMs to network operations covers a wide range of approaches, from one-shot query translation to multi-step autonomous reasoning.

The simplest approach translates user queries into tool-specific commands.
A representative example is AskBatfish~\cite{ref16}, which converts natural language questions into Batfish API calls. However, it does not support multi-step analysis or coordination across tools.

Intent-based approaches focus on translating operator intent into specific network configurations.
INTA~\cite{ref13}, a RAG-based agent, achieves a syntactic accuracy of 98.15\% in translating intent into configurations, while Confucius~\cite{ref15} proposes automated intent-based network management using a multi-agent architecture.
However, these studies primarily address configuration \emph{writing} tasks and do not adequately address \emph{reasoning}, i.e., drawing logical conclusions from existing configurations.

Recently, research on performance improvement through multi-agent system (MAS) architectures has gained increasing attention.
KubeLLM~\cite{ref14} improves Kubernetes management accuracy over single-agent baselines by separating knowledge agents and tool agents.
NIKA~\cite{wang2025network_arena} is an evaluation arena featuring five scenarios and over 640 incidents, exposing more than 30 tools via the MCP interface and highlighting limitations in fault detection and root cause identification for GPT-4-class models.
However, these studies do not clearly distinguish whether the reported performance gains arise from the structural design of the agents or from the capabilities of the integrated tools.

\subsection{Research Positioning}

Existing research primarily focuses on either benchmarks or systems. Benchmarks such as TeleQnA and NetConfEval provide criteria for measuring LLM capabilities but lack systems to address the identified limitations. Conversely, systems such as NIKA and INTA propose network management frameworks but lack systematic performance evaluation within controlled benchmarks. Furthermore, as discussed earlier, existing multi-agent studies report results without isolating whether performance improvements originate from the agent architecture or the integrated tools.

This paper bridges these three gaps by integrating a benchmark, an evaluation metric, and a system into a unified framework. First, we define the evaluation problem using NetConfigQA~2.0 and TA-Acc and quantify LLM limitations through a single-LLM baseline. Next, we isolate the effect of the agent architecture through \emph{Pure MAS} experiments and then evaluate how the tool-integrated system, NetAlly, compensates for these limitations. Beyond prior work that claims performance gains from MAS, we experimentally decouple and analyze whether the observed improvements arise from the collaborative structure among agents or from the integrated network analysis tools.
