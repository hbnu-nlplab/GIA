\section{Introduction}
\IEEEPARstart{T}{he} rapid adoption of cloud computing, SDN, and NFV has significantly increased the complexity of modern network management.
Conventional approaches rely heavily on operator expertise and manual processes, making them error-prone and difficult to scale~\cite{mao2017neural, meng2020interpreting}.
Large Language Models (LLMs) have emerged as a promising paradigm for network management automation, demonstrating the ability to analyze configuration documents, interpret operator queries, and generate configuration commands~\cite{liu2025large, wu2024netllm}.
However, single LLM-based approaches face inherent limitations: tasks such as tool interfacing, dynamic environment perception, and precise reasoning over long contexts exceed simple text generation, often resulting in hallucinated outputs~\cite{bekri2025bridging, wang2024netconfeval}.
Multi-Agent Systems (MAS), where agents collaboratively solve tasks through role division, have been proposed to address these limitations~\cite{ref2, arzo2021multiagent, bimo2025intentbased}.

% 클라우드 컴퓨팅, SDN, NFV의 급속한 도입은 현대 네트워크 관리의 복잡성을 크게 증가시켰다. 기존 접근 방식은 운영자의 전문성과 수작업 프로세스에 크게 의존하여 오류 발생 가능성이 높고 확장성이 떨어진다. 대규모 언어 모델(LLM)은 설정 문서를 분석하고, 운영자의 질의를 해석하며, 설정 명령을 생성할 수 있는 능력을 보이며 네트워크 관리 자동화를 위한 유망한 패러다임으로 부상하였다. 그러나 단일 LLM 기반 접근 방식은 본질적인 한계를 가진다. 도구 인터페이싱, 동적 환경 인식, 긴 컨텍스트에 대한 정밀한 추론과 같은 작업은 단순한 텍스트 생성 능력을 초과하며, 종종 환각된 출력을 초래한다. 이러한 한계를 해결하기 위해 역할 분담을 통해 협력적으로 문제를 해결하는 다중 에이전트 시스템(MAS)이 제안되었다.

Despite this progress, rigorously evaluating LLM capabilities on network configuration files remains an open challenge.
Existing benchmarks assess knowledge-based QA over standards documents~\cite{ref9, ref10} or configuration generation~\cite{wang2024netconfeval}, but none systematically evaluate \textbf{behavioral inference}---the ability to reason about network behavior from configuration files alone.
Three gaps remain unaddressed: (1) no benchmark distinguishes cognitive difficulty levels from fact extraction to fault impact analysis; (2) standard NLP metrics such as BERTScore and Exact Match fail to handle IP address semantics or set ordering; and (3) no automated pipeline generates QA pairs across diverse topologies at scale.

% 이러한 진전에도 불구하고, 네트워크 설정 파일에 대한 LLM의 성능을 엄밀하게 평가하는 것은 여전히 미해결 과제로 남아 있다. 기존 벤치마크는 표준 문서에 대한 지식 기반 질의응답이나 설정 생성에 초점을 맞추고 있지만, 설정 파일만을 기반으로 네트워크 동작을 추론하는 능력(behavioral inference)을 체계적으로 평가하지는 못한다. 세 가지 한계가 존재한다. 첫째, 사실 추출부터 장애 영향 분석까지의 인지 난이도를 구분하는 벤치마크가 없다. 둘째, BERTScore나 Exact Match와 같은 기존 NLP 지표는 IP 주소의 의미나 집합 순서를 적절히 반영하지 못한다. 셋째, 다양한 토폴로지에 대해 대규모로 QA 쌍을 생성하는 자동화된 파이프라인이 존재하지 않는다.
This paper extends our prior work~\cite{netagent2026} with two contributions.
\begin{itemize}
  \item \textbf{C1.} \emph{Automated Benchmark and Evaluation Metric.}
    We construct \textbf{NetConfigQA~2.0}, which automatically generates QA pairs across five cognitive difficulty levels via a Dual-Path pipeline combining configuration files with Batfish simulation.
    The dataset scales to arbitrary topology sizes by replacing only configuration and policy files.
    We also propose \textbf{TA-Acc}, an evaluation metric that reflects the structural properties of network data.

  \item \textbf{C2.} \emph{MCP-Based Tool-Integrated Multi-Agent System.}
    To mitigate the simulation barrier identified in our benchmark evaluation, we propose \textbf{NetAlly}, a multi-agent system accessing PNETLab, Cisco NSO, and Batfish via MCP.
    We evaluate six LLMs across four topologies (10--40 nodes, 9,473 QA pairs) under three conditions: single LLM, MAS without tools, and full NetAlly with tool integration.
\end{itemize}

The remainder of this paper is organized as follows.
Section~2 reviews related work.
Section~3 introduces NetConfigQA~2.0 and TA-Acc.
Section~4 presents the NetAgent base system.
Section~5 describes the NetAlly system.
Section~6 reports experimental results.
Section~7 discusses implications and limitations.
Section~8 concludes.
