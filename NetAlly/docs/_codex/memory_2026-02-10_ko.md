# NetAlly x PNETLab: 쿠키 없는(LabFS) 토폴로지 복제/시각화 메모 (2026-02-10)

> 주의: 이 문서에는 **비밀번호/쿠키/JWT/API 키 같은 민감정보를 기록하지 않는다.**

## 1) 우리가 달성한 목표(현 상태)

### 1.1 PNETLab 토폴로지 "복제" (쿠키 없이)
- PNETLab 웹/API 인증(CAPTCHA/XSRF/쿠키 만료)에 의존하지 않고, PNETLab 파일 시스템(LabFS)에서 토폴로지를 복제한다.
- 입력 데이터:
  - `.unl` (XML): 노드 위치(left/top), 아이콘, 네트워크/연결 메타데이터
  - `/opt/unetlab/tmp/*/*/wrapper.txt`: 실행 중 노드의 콘솔 포트(best-effort)
- API:
  - `GET /api/topology/pnetlab`
- 구현:
  - `NetAlly/agent/pnetlab_labfs.py`
  - `NetAlly/main.py`

### 1.2 아이콘 처리(정적 우선 + 프록시 fallback)
- 프론트는 아래 순서로 아이콘을 렌더한다:
  1. 정적: `/pnetlab-icons/<icon_name>` (레포에 포함된 파일)
  2. fallback: `GET /api/pnetlab/icon/<icon_name>` (컨테이너가 PNETLab 아이콘 폴더를 볼 수 있을 때)
  3. 최종: 기본 아이콘(lucide 등)
- 구현:
  - 정적 경로: `NetAlly/frontend/public/pnetlab-icons/`
  - 프록시: `NetAlly/main.py` (`/api/pnetlab/icon/{icon_name}`)
  - 렌더: `NetAlly/frontend/src/components/DeviceNode.tsx`, `NetAlly/frontend/src/components/NetworkNode.tsx`

### 1.3 질문 결과 시각화(룰 기반 하이라이트)
- SSE 이벤트에서 `viz` 힌트를 내려 UI가 노드/엣지를 하이라이트한다.
- 목적: “예쁘게”보다 “데모에서 확실히 보이는 피드백” 우선.

### 1.4 아이콘 자동 동기화(UNL 기반)
- `.unl`이 참조하는 아이콘 파일명만 추출해서 프론트 정적 폴더로 동기화한다.
- 스크립트:
  - `NetAlly/scripts/pnetlab_sync_icons.py`

## 2) 핵심 결정(데모/운영 관점)
- PNETLab 자동화 범위는 **읽기 전용**이 기본(토폴로지 복제/아이콘/포트).
- "쿠키 자동화"는 데모 안정성에 불리하므로 가능한 한 사용하지 않는다.
- NetAlly는 **PNETLab VM 내부에서 Docker 컨테이너로 실행**된다.
  - 따라서 `labfs_local`이 되려면 컨테이너가 호스트의 `/opt/unetlab`을 볼 수 있어야 한다.

## 3) 배포 전제(진짜 중요한 부분)

### 3.1 컨테이너에서 LabFS가 보이게 해야 함
PNETLab VM 내부에서 NetAlly가 컨테이너로 실행되더라도,
컨테이너는 기본적으로 호스트의 `/opt/unetlab`을 못 본다.

따라서 **반드시** 아래 마운트가 필요하다:
- `/opt/unetlab:/opt/unetlab:ro` (read-only 권장)

문서/주석 업데이트:
- `NetAlly/docs/pnetlab_deployment_guide.md`에 LabFS 섹션 추가
- `NetAlly/docker-compose.yml`에 마운트 예시 주석 추가

## 4) 런타임 설정(최소)

### 4.1 쿠키 없는 토폴로지 복제 (권장)
```bash
PNETLAB_INVENTORY_BACKEND=labfs_local
PNETLAB_LAB_NAME=test_nso
# 또는:
# PNETLAB_LAB_PATH=/opt/unetlab/labs/test_nso.unl
```

### 4.2 아이콘 동기화(정적 고정)
```bash
cd NetAlly
PNETLAB_INVENTORY_BACKEND=labfs_local \
PNETLAB_LAB_NAME=test_nso \
uv run python scripts/pnetlab_sync_icons.py
```

> 참고: 컨테이너 내부에서 실행할 경우, 레포 파일시스템에 쓰기 권한/경로가 있어야 한다.
> (일반적으로는 NetAlly 소스가 컨테이너에 포함되어 있거나, 볼륨으로 마운트되어 있어야 함)

## 5) 자동 감지 동작(요약)
- `PNETLAB_INVENTORY_BACKEND`가 비어있으면:
  - `/opt/unetlab/labs`가 있으면 `labfs_local` 우선
  - 아니면 `PNETLAB_SSH_HOST`가 있으면 `labfs_ssh`
  - 그 외엔 API fallback

## 6) 남은 "실 구현" 작업(대부분 운영/검증)

### 6.1 PNETLab Docker Node 설정에서 마운트 가능 여부 확인 (1순위)
- 목표: NetAlly 컨테이너 안에서 `/opt/unetlab/labs/*.unl`을 읽을 수 있는지 확인
- 확인 커맨드(컨테이너 내부):
  - `ls -la /opt/unetlab/labs | head`

### 6.2 실제 랩으로 토폴로지 동일성 검증
- `GET /api/topology/pnetlab` 결과로:
  - 노드 수/이름/위치가 PNETLab 화면과 대체로 일치하는지
  - hidden 네트워크(visibility=0) + endpoints=2 케이스에서 device-device edge가 잘 나오는지
  - 네트워크 hub 노드(`net:<id>`)가 필요할 때만 생기는지

### 6.3 아이콘 동기화 결과 검증
- `.unl`에서 참조하는 아이콘이 `/pnetlab-icons/<name>`로 뜨는지 확인
- 없으면 `/api/pnetlab/icon/<name>` fallback이 동작하는지 확인

### 6.4 하이라이트(시각화) 매칭 검증
- 질문 결과(특히 traceroute path)의 hostname과 PNETLab 노드명이 다르면 하이라이트가 빗나갈 수 있다.
- 필요 시 다음 보완 중 하나:
  - (가벼운) 대소문자 정규화/alias 매핑
  - (추가) node data에 hostname/alias를 넣어 매칭 강화

## 9) 2026-02-11 시각화 오버레이 보강(적용 완료)

### 9.1 무엇을 고쳤는가
- `TopologyPanel`에서 `viz` 변경 시 토폴로지를 재조회하던 흐름을 분리:
  - 이전: `viz` 변경 -> `fetchTopology()` 재실행 가능
  - 현재: `viz`는 기존 노드/엣지에 오버레이만 적용 (불필요한 깜빡임/재배치 방지)
- 엣지 기본 스타일 보존:
  - edge 생성 시 `__baseStyle`, `__baseMarker`를 저장하고 오버레이 해제 시 복원
- `NetworkNode`도 `highlight/highlightMode`를 반영:
  - device뿐 아니라 hub/cloud(`net:*`) 노드도 path/focus 강조 가능
- 노드 매칭 강화:
  - 소문자 + 공백 제거 + `.` suffix(도메인) 축약 + `_`/`-` 변형을 alias key로 취급
  - `id/label/hostname/name/alias/aliases` 후보를 인덱싱해 canonical 매칭
- path 엣지 fallback:
  - 직접 edge가 없더라도 공통 `net:*` 허브가 있으면 `A-hub`, `B-hub` 엣지를 강조
