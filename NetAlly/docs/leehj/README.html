2. 환경 한눈에 보기

팀원이 192.168.0.80:3000 접속 → NetAlly가 4개 NSO 중 labd:38080 (현재 active)로 RESTCONF 호출 → NSO가 vmnet8 통해 PNETLab의 10.10.10.x device에 SSH 들어가서 config 읽음.

3. 왜 NSO를 4개로 나눴나

핵심 제약

모든 lab의 OOB(management) IP가 10.10.10.11~로 동일하다. 예: LabA의 P1 = 10.10.10.11, LabB의 P1 = 10.10.10.11.

이 때문에 PNETLab에서는 한 번에 하나의 lab만 띄울 수 있다. 동시에 두 lab을 켜면 %IP-4-DUPADDR 충돌이 나고 NSO sync가 깨진다.

해결: NSO를 lab별로 분리

NSO 인스턴스를 lab마다 따로 두면 각자 자기 CDB에 device 정보를 갖는다. 같은 IP라도 다른 NSO 안에 있으니 inventory 충돌이 없다.

장점설명
충돌 회피같은 IP라도 NSO가 달라서 inventory 충돌 없음
병렬 운영lab을 전환해도 다른 lab의 CDB는 보존됨
독립 디버깅한 lab의 sync 문제가 다른 lab에 영향 X
인계 안정성LabD 데이터 954MB가 호스트에 마운트되어 컨테이너 재시작에도 보존

4. 왜 Tailscale 떼고 vmnet8을 썼나

두 가지 라우팅 비교

같은 박스(A5000) 안의 PNETLab VM과 통신할 때 두 가지 경로가 있다.

🐢 옛 경로: Tailscale

  • RTT: 2~3ms (커널 fwmark 룰 거침)
  • 도커 컨테이너에서 안 됨 — Tailscale 정책 라우팅이 fwmark 있는 패킷만 처리
  • Tailscale 데몬 죽으면 OOB 통신 끊김
  • 팀원도 Tailscale 가입해야 접속 가능

⚡ 현재 경로: vmnet8

  • RTT: 0.1ms (vmnet8 가상 스위치, 메모리 hop)
  • 도커 컨테이너에서도 작동 (main routing table 사용)
  • Tailscale 죽어도 OOB 통신 살아있음
  • 팀원은 LAN IP만 알면 됨 (Tailscale 가입 불필요)

vmnet8 라우팅 작동 원리

# 영구화된 설정 (재부팅 후에도 살아있음)
ip route show 10.10.10.0/24
  → 10.10.10.0/24 via 192.168.110.132 dev vmnet8

sudo iptables -t nat -L POSTROUTING -n | grep '10.10.10'
  → MASQUERADE  all  --  0.0.0.0/0  10.10.10.0/24

sudo systemctl status pnetlab-oob-route.service
  → active (exited)

6. 평가 파이프라인 흐름

채점: TA-Acc (Type-Aware Accuracy)

BERTScore는 네트워크 도메인에서 변별력이 없다(모두 0.9+). TA-Acc는 answer_type별로 비교 방식을 바꾼다:

answer_type비교예
set_strF1 (순서 무관){Leaf1, Leaf2} = Leaf2, Leaf1
pathOrdered Exact MatchA→B→C ≠ A→C→B
scalar_str정규화 후 ExactGi0/0 ≈ GigabitEthernet 0/0
bool정규화 비교"true" = "yes"
map_str_intKey-Value F1{P1:5, P2:3}

결과 폴더 구조

NetAlly/results/                   ← 단일 실행 raw + 채점
├── netally_eval_direct_Dataset_20260417_175633.json   raw 답변
├── ..._analyzed.json                                  채점 추가
├── ..._analyzed_scorecard.md      ★ 사람이 보는 점수표
├── ..._analyzed_summary.md         level별 짧은 요약
├── ..._analyzed_detailed.csv       Excel용 raw
└── ..._analyzed_errors.json        실패만 모음

NetAlly/result3/                   ← 여러 모델/lab 묶은 비교
├── scorecards/{strict,relaxed}/
├── tables/                         논문용 표
└── raw_index.md

7. 트러블슈팅 카드

🔑 ssh-rsa host key 검증 실패

증상: Could not verify ssh-rsa host key with fingerprint ...

PORT=38080; DEV=P1
curl -s -u admin:admin -X POST \
  -H "Content-Type: application/yang-data+json" \
  "http://localhost:$PORT/restconf/data/tailf-ncs:devices/device=$DEV/ssh/fetch-host-keys"
curl -s -u admin:admin -X POST \
  -H "Content-Type: application/yang-data+json" \
  "http://localhost:$PORT/restconf/data/tailf-ncs:devices/device=$DEV/sync-from"

🔌 8111 포트 점유

sudo ss -tlnp | grep ':8111'
pkill -u $USER -f 'uvicorn main:app'

다른 사용자(leehj 외)의 프로세스라면 강제 종료 X. 별도 포트 사용 고려.

📡 OOB 10.10.10.x ping 안 됨

ip route show 10.10.10.0/24
sudo iptables -t nat -L POSTROUTING -n | grep '10.10.10'
sudo systemctl status pnetlab-oob-route.service

PNETLab VM이 꺼져있으면 vmnet8 사라짐 → VMware Workstation에서 PNETLab 먼저 start.

⚠️ IP 중복 (DUPADDR)

증상: console에 %IP-4-DUPADDR

원인: PNETLab pnet0에 이전 lab의 vunl* 인터페이스 잔존.

# PNETLab VM에서
bridge fdb show br pnet0 | grep '50:ba:bd:00:3e:03'
ip link set vunl62_3 down

🐳 NSO 컨테이너 죽음

docker ps -a | grep cisco-nso
docker start cisco-nso-labd
docker logs --tail 30 cisco-nso-labd

CDB는 호스트 마운트 → 재시작해도 데이터 그대로.

👥 authgroup 누락 (LabA/C 첫 등록)

LabA의 authgroup은 Research_Institute_Internal_DC. 빈 NSO에는 default만 있음.

docker exec cisco-nso-laba /root/nso-6.6/bin/ncs_cli -u admin -C <<'EOF'
config
devices authgroups group Research_Institute_Internal_DC \
  default-map remote-name admin remote-password admin
commit
EOF
