# 7.0 실전 서비스 구현 전략 (Real Service Strategy)

> **📍 네비게이션**: [← 6.2 도메인 가이드](./6.2_Network_Domains_Guide.md) | [INDEX](./6.0_Network_Dataset_Index.md)

이 문서는 Phase 1 데이터셋 구축 과정에서 **"실제 서비스(Real Service)"**를 각 네트워크 도메인에 통합하기 위한 전략과 구현 가이드입니다.

---

## 1. 핵심 전략: 서비스는 "검증 프로브(Prove)"다

우리의 목표는 애플리케이션 개발이 아닙니다. 서비스는 **네트워크가 정상적으로 동작함을 증명하는 가장 확실한 도구**로서 도입됩니다.

- **역할**: "그럴듯한 쇼"가 아니라, **네트워크 설정 상태를 판정하는 기준**
- **원칙**:
  1. **단순화**: 각 랩당 **서비스 1개 + 호스트 2대** (서버/클라이언트)
  2. **가시성**: 사람 눈으로 확인 가능해야 함 (웹 페이지, 영상 재생)
  3. **정량화**: 자동 채점이 가능해야 함 (HTTP 200 OK, Throughput 수치)
  4. **현실성**: 현업에서 해당 네트워크 도메인을 쓰는 **진짜 목적**과 부합해야 함

---

## 2. 5대 도메인별 리얼 서비스 매핑

각 네트워크의 특성을 가장 잘 대변하는 "단 하나의 실제 서비스"를 구축합니다.

| 도메인           | 서비스 명칭      | 구현 방식 (Docker)                           | 검증 포인트 (Human/Auto)                                               |
| :--------------- | :--------------- | :------------------------------------------- | :--------------------------------------------------------------------- |
| **1. Backbone**  | **사내 웹 포털** | **HTTPS (Nginx)**<br>코어망을 경유해 접속    | 👁️ 브라우저 접속<br>🤖 `curl -k https://...` (200 OK)                  |
| **2. BGP Edge**  | **Public SaaS**  | **Web + DNS**<br>외부 인터넷 서비스 모사     | 👁️ 도메인 접속 (service.example)<br>🤖 `dig` + `curl` (경로 변경 확인) |
| **3. L3VPN**     | **업무 협업 툴** | **Gitea (Git)**<br>지점 간 소스코드 공유     | 👁️ Git Clone / 웹 로그인<br>🤖 `git clone` 성공 여부                   |
| **4. L2VPN**     | **파일 공유**    | **Samba (SMB)**<br>같은 서브넷에서 파일 전송 | 👁️ 공유폴더 탐색<br>🤖 파일 해시 비교 (`sha256sum`)                    |
| **5. Multicast** | **IPTV 방송**    | **FFmpeg 스트리밍**<br>실시간 영상 송출      | 👁️ VLC 영상 재생 (검은 화면=장애)<br>🤖 패킷 카운트 / 프레임 로그      |

---

## 3. 구현 아키텍처 (Service Kit)

모든 랩에 공통적으로 적용되는 **"Service Kit"** 구조를 사용합니다. 복잡성을 줄이기 위해 각 랩에 딱 2대의 리눅스 컨테이너만 추가합니다.

### 3.1 호스트 구성 (PNETLab/Docker)

각 랩마다 다음 두 종류의 노드를 추가합니다. Alpine Linux 기반의 가벼운 이미지를 권장합니다.

- **SVC-SRV (Service Server)**: 데이터센터/본사 위치
- **SVC-CLI (Verifier/Probe)**: 지사/가입자망 위치

### 3.2 도메인별 상세 구축 가이드

#### ① Backbone 랩: 사내 웹 포털 (HTTPS)

- **목표**: "코어망을 통과해 안전하게 접속됨"을 증명
- **구성**:
  - **Server**: Nginx (Self-signed 인증서 생성)
  - **Client**: `curl`, `firefox` (VNC)
- **검증 커맨드**:
  ```bash
  # 연결 성공 확인 (200 OK)
  curl -k -s -o /dev/null -w "%{http_code}" https://10.0.1.100
  # 경로 확인 (코어 경유 여부)
  traceroute 10.0.1.100
  ```

#### ② BGP Edge 랩: Public SaaS (Web + DNS)

- **목표**: "인터넷 경로 정책(BGP)에 따라 접속 경로가 바뀜"을 증명
- **구성**:
  - **External Server**: Nginx + DNS (Bind9/Dnsmasq)
  - **Internal Client**: `dig`로 DNS 질의 후 접속
- **검증 시나리오**:
  - 평상시: ISP A 경유 접속
  - 장애시: ISP B로 경로 우회 (Traceroute로 확인)

#### ③ L3VPN 랩: 업무 협업 툴 (Gitea)

- **목표**: "VRF로 격리된 전용망에서만 접속 가능함"을 증명 << **가장 강력한 데모**
- **구성**:
  - **Branch-HQ**: Gitea 컨테이너 구동
  - **Branch-Site**: Git Client
- **검증 커맨드**:
  ```bash
  git clone http://10.2.1.100/repo.git
  ```
  - **성공**: VRF 라우팅 정상
  - **실패 (Timeout/500)**: RT(Route Target) 설정 오류

#### ④ L2VPN 랩: 파일 공유 (SMB)

- **목표**: "같은 L2 네트워크(서브넷) 상에 있는 것처럼 동작함"을 증명
- **구성**:
  - **Server (Site A)**: Samba 공유 폴더 (`/share`)
  - **Client (Site B)**: `smbclient`
- **검증 커맨드**:
  ```bash
  # 파일 다운로드 및 무결성 검사
  smbclient //10.3.1.100/share -U user%pass -c 'get data.bin'
  sha256sum data.bin
  ```

#### ④ Multicast 랩: IPTV 방송

- **목표**: "멀티캐스트 트리가 정상일 때만 화면이 나옴"을 증명 (시각적 효과 최강)
- **구성**:
  - **Source**: FFmpeg로 UDP 스트림 송출
    ```bash
    ffmpeg -re -f lavfi -i testsrc=size=640x360:rate=30 -f mpegts udp://239.1.1.1:5000
    ```
  - **Receiver**: FFmpeg/VLC로 수신
    ```bash
    timeout 5 ffmpeg -i udp://239.1.1.1:5000 -f null -
    ```

## 4. Phase 1 vs Phase 2 활용 계획

이 서비스 구축은 단순히 Phase 1의 데모용이 아닙니다. Phase 2 연구의 핵심 장치로 이어집니다.

### Phase 1: Dataset Generation

- **목표**: "설정 파일(XML)"과 "서비스 상태"의 연관성 학습
- **활용**:
  - Golden State에서 서비스가 정상임을 보여줌 (Ground Truth)
  - "이 설정(VRF) 덕분에 Gitea 접속이 가능하다"는 설명 생성

### Phase 2: Fault Injection & Recovery

- **목표**: 장애 복구 성공 여부를 **서비스 재개**로 판정
- **시나리오 예시**:
  - **장애**: RT Import 실수 → Gitea 접속 불가 (500/Timeout)
  - **진단**: LLM이 설정 오류 식별
  - **복구**: NSO로 RT 수정
  - **판정**: `verify_service()` 실행 → Git Clone 성공 → **"복구 완료"**
