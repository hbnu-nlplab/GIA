## 5. 장비 CLI 설정 [Backbone]

본 절차는 연구기관 내부 데이터센터 네트워크의 핵심인 Backbone 라우터 **P1**에 대한 초기 기본 설정 및 OSPF 라우팅 프로토콜 설정을 다룹니다.

### **5-0. 설정 목표**

P1, P2, P3, P4 라우터가 IP로 상호 연결되고, **OSPF**를 통해 자동으로 경로를 학습하는 '살아 있는 망' 상태를 구축하는 것이 목표입니다.

**주요 개념:**

- **인터페이스 (Interface)**: 라우터의 물리적 랜선 포트입니다. (예: Gi0/0, Gi0/1)
    
- **IP 주소**: 장비의 고유 식별 주소로, 통신을 위해 필수적입니다.
    
- **OSPF**: 네트워크 장비 간 경로 정보를 자동으로 교환하는 동적 길찾기 프로토콜입니다.
    

---

### **5-1. 장비 전원 인가 및 콘솔 접속**

1. **전원 ON**: PNETLab에서 P1 ~ P4 라우터 모두를 선택한 후, ▶ (Start) 버튼을 클릭하여 장비에 전원을 인가합니다.
    
2. **콘솔 접속**: P1을 더블클릭하여 콘솔 세션을 시작합니다.
    
3. **초기 마법사 비활성화**: 초기 설정 대화 상자가 나타나면 `no`를 입력하여 직접 수동 설정을 시작합니다.

```bash
Would you like to enter the initial configuration dialog? [yes/no]: no
```


---

### **5-2. Cisco 기본 모드 진입**

설정은 일반 사용자 모드에서 관리자 모드, 그리고 전역 설정 모드로 순차적으로 진입하여 진행됩니다.

1. **관리자 모드 (Privileged EXEC Mode) 진입**
```Bash
Router> enable
Router#
```
    
2. **전역 설정 모드 (Global Configuration Mode) 진입**
    
    Bash
    
    ```
    Router# configure terminal
    Router(config)#
    ```
    

---

### **5-3. P1 기본 설정 적용**

장비 식별, 오타 방지, 라우팅 기능 활성화 등 필수적인 설정을 적용합니다.

1. 장비 이름 변경
    
    (목적: 장비 구분을 명확히 하며, QA 질문 및 로그 분석의 기준이 됩니다.)
    
    Bash
    
    ```
    P1(config)# hostname P1
    P1(config)#
    ```
    
2. 오타 시 DNS 검색 비활성화
    
    (목적: 명령어 오타 시 Cisco가 DNS를 찾느라 30초간 멈추는 현상, 즉 '초심자 멘탈 파괴 1순위'를 방지합니다.)
    
    Bash
    
    ```
    P1(config)# no ip domain-lookup
    ```
    
3. 라우팅 기능 활성화
    
    (목적: 라우터가 패킷을 전달하는 본연의 역할을 수행하도록 활성화합니다.)
    
    Bash
    
    ```
    P1(config)# ip routing
    ```
    

---

### **5-4. 인터페이스 및 IP 주소 설정**

Backbone 네트워크 연결을 위한 인터페이스와 OSPF Router ID로 사용될 루프백 인터페이스에 IP 주소를 할당합니다.

1. P1 ↔ P2 직결 링크 설정 (Gi0/0)
    
    (IP: 10.0.0.0/31은 라우터 직결 링크에 최적화된 서브넷입니다.)
    
    Bash
    
    ```
    P1(config)# interface gigabitEthernet0/0
    P1(config-if)# ip address 10.0.0.0 255.255.255.254
    P1(config-if)# no shutdown
    P1(config-if)# exit
    ```
    
    - `no shutdown`: 인터페이스를 수동으로 활성화합니다.
        
2. **P1 ↔ P4 직결 링크 설정 (Gi0/1)**
    
    Bash
    
    ```
    P1(config)# interface gigabitEthernet0/1
    P1(config-if)# ip address 10.0.0.7 255.255.255.254
    P1(config-if)# no shutdown
    P1(config-if)# exit
    ```
    
3. P1 루프백 인터페이스 설정 (Loopback0)
    
    (목적: OSPF의 **고유 식별자(Router ID)**로 사용되며, 물리 인터페이스 상태와 무관하게 항상 유지됩니다.)
    
    Bash
    
    ```
    P1(config)# interface loopback0
    P1(config-if)# ip address 10.255.0.1 255.255.255.255
    P1(config-if)# exit
    ```
    

---

### **5-5. OSPF (자동 길찾기) 설정**

Backbone 영역인 Area 0에 P1을 포함시키고, Router ID를 지정하여 OSPF 프로세스를 활성화합니다.

1. **OSPF 프로세스 시작 및 Router ID 지정**
    
    Bash
    
    ```
    P1(config)# router ospf 1
    P1(config-router)# router-id 10.255.0.1
    ```
    
    - `router ospf 1`: OSPF 프로세스 번호 1을 시작합니다.
        
    - `router-id`: P1을 대표하는 ID를 루프백 주소로 지정합니다.
        
2. OSPF 네트워크 영역 지정
    
    (목적: 지정된 IP 대역과 루프백 주소를 OSPF에 참여시켜 Area 0 (Backbone 영역)으로 라우팅 정보를 교환하도록 합니다.)
    
    Bash
    
    ```
    P1(config-router)# network 10.0.0.0 0.0.0.255 area 0
    P1(config-router)# network 10.255.0.1 0.0.0.0 area 0
    P1(config-router)# exit
    ```
    

### **5-6. 설정 저장**

적용된 설정을 영구적으로 저장하여 재부팅 후에도 유지되도록 합니다.

Bash

```
P1(config)# end
P1# write memory
```

**현재 상태:** P1은 IP 주소 할당 및 인터페이스 활성화, OSPF 준비가 완료되었습니다.


### **5-7. P2 설정 (P1과의 비교 및 이해)**

Backbone 라우터 P1, P2, P3, P4는 모두 동일한 역할을 수행하며, **`ip routing`, `no ip domain-lookup`, `loopback0` 설정, `OSPF area 0`** 이라는 공통점을 가집니다. 차이점은 인터페이스 IP, Loopback IP, 그리고 연결된 이웃뿐입니다.

#### **5-7-1. 기본 모드 진입 및 호스트네임 설정**

P1과 100% 동일하게 관리자 모드와 전역 설정 모드로 진입하고, 기본 설정을 적용합니다.

Bash

```
Router> enable
Router# configure terminal
Router(config)# hostname P2
P2(config)# no ip domain-lookup
P2(config)# ip routing
```

#### **5-7-2. P2 인터페이스 및 IP 주소 설정 (핵심)**

|**링크**|**대역**|**P2의 역할**|**IP 주소**|
|---|---|---|---|
|**P2 ↔ P1 링크 (Gi0/0)**|10.0.0.0/31|P1이 `.0`을 사용했으므로, P2는 **`.1`**을 사용합니다.|`10.0.0.1 255.255.255.254`|
|**P2 ↔ P3 링크 (Gi0/1)**|10.0.0.2/31|다음 구간의 시작점으로, P2가 **`.2`**를 사용합니다.|`10.0.0.2 255.255.255.254`|
|**P2 ↔ PE1 링크 (Gi0/2)**|10.0.1.0/31|PE1으로 향하는 링크의 시작점으로, P2가 **`.0`**을 사용합니다.|`10.0.1.0 255.255.255.254`|

**P2 ↔ P1 링크 설정 (Gi0/0)**

Bash

```
P2(config)# interface gigabitEthernet0/0
P2(config-if)# ip address 10.0.0.1 255.255.255.254
P2(config-if)# no shutdown
P2(config-if)# exit
```

**P2 ↔ P3 링크 설정 (Gi0/1)**

Bash

```
P2(config)# interface gigabitEthernet0/1
P2(config-if)# ip address 10.0.0.2 255.255.255.254
P2(config-if)# no shutdown
P2(config-if)# exit
```

**P2 ↔ PE1 링크 설정 (Gi0/2)**

Bash

```
P2(config)# interface gigabitEthernet0/2
P2(config-if)# ip address 10.0.1.0 255.255.255.254
P2(config-if)# no shutdown
P2(config-if)# exit
```

#### **5-7-3. P2 루프백 및 OSPF 설정**

Loopback IP는 P1이 `.1`을 썼으므로 P2는 **`.2`**를 사용합니다. Router ID 역시 이에 맞춰 변경합니다.

1. **Loopback 인터페이스 설정**
    
    Bash
    
    ```
    P2(config)# interface loopback0
    P2(config-if)# ip address 10.255.0.2 255.255.255.255
    P2(config-if)# exit
    ```
    
2. **OSPF 설정**
    
    Bash
    
    ```
    P2(config)# router ospf 1
    P2(config-router)# router-id 10.255.0.2
    P2(config-router)# network 10.0.0.0 0.0.0.255 area 0
    P2(config-router)# network 10.0.1.0 0.0.0.255 area 0
    P2(config-router)# network 10.255.0.2 0.0.0.0 area 0
    P2(config-router)# exit
    ```
    
    > 📌 **참고**: `10.0.0.0 0.0.0.255`와 같이 크게 Wildcard Mask를 설정하는 이유는 실습 단계에서 단순화를 위함입니다. 이를 통해 나중에 "과도한 network statement" 관련 QA 질문도 생성할 수 있습니다.
    

#### **5-7-4. 설정 저장**

Bash

```
P2(config)# end
P2# write memory
```

### **5-10. DC Edge (PE1, PE2)의 OSPF 편입**

이 단계의 목표는 **DC Edge(PE1, PE2) 라우터**를 기존 Backbone(P1~P4)과 동일한 **OSPF Area 0**에 편입시켜, Backbone ↔ DC 경계가 유기적으로 연결되고 경로 계산이 자동으로 이루어지도록 하는 것입니다.

> 개념 이해: PE의 역할
> 
> 현재 단계에서 PE는 P1~P4와 구조적으로는 같습니다. 다만, PE는 나중에 **VRF(Virtual Routing and Forwarding)**가 생성되어 외부(Backbone)와 내부(DC Leaf/Server)를 연결하는 관문 역할을 하게 됩니다.

#### **5-10-1. PE1 설정 (P2 연결)**

PE1은 P2 라우터에 연결되어 있으며, 설정 원리는 P1~P4와 동일합니다.

1. 기본 모드 진입 및 호스트네임 설정
    
    (장비 구분을 명확히 하고, 라우팅 기능을 활성화합니다.)
    
    Bash
    
    ```
    Router> enable
    Router# configure terminal
    Router(config)# hostname PE1

## **6. 논리적 분리 구축: VRF 생성**

### **6-0. VRF의 역할 및 중요성**

VRF는 단일 물리적 라우터 장비 위에 여러 개의 독립적인 **라우팅 테이블(Routing Table)**을 생성하여, 각 연구 그룹(AI, BIO, HPC)이 서로의 통신 경로를 볼 수 없도록 **논리적으로 분리**하는 기술입니다.

|**구분**|**Backbone (P1~P4)**|**PE (PE1/PE2) - 지금부터**|
|---|---|---|
|**라우팅 테이블**|단일 Global 테이블|**Global + VRF_AI + VRF_BIO + VRF_HPC**|
|**VRF 한 문장 요약**|같은 망에 여러 개의 **독립적인 네트워크(Router)** 생성||

이 단계를 통해 "누가 누구랑 통신하면 안 되는지"에 대한 보안 및 정책 질문의 기반이 완성됩니다.

### **6-1. VRF 설계 및 구성 요소 이해**

3개의 연구 그룹(AI, BIO, HPC)에 대해 VRF를 생성하며, 각 VRF는 고유한 식별자인 **RD(Route Distinguisher)**와 경로 교환 태그인 **RT(Route Target)**를 가집니다.

|**VRF 이름**|**의미**|**RD (Route Distinguisher)**|**RT (Route Target)**|
|---|---|---|---|
|`VRF_AI`|AI 연구실|`65000:1`|`65000:1`|
|`VRF_BIO`|바이오 연구실|`65000:2`|`65000:2`|
|`VRF_HPC`|HPC 연구실|`65000:3`|`65000:3`|

#### **6-1-1. RD(Route Distinguisher)**

- **역할**: VPNv4 주소의 접두어(Prefix) 역할을 합니다.
    
- **이유**: 서로 다른 VRF에 동일한 IP 주소(예: `192.168.1.0/24`)가 사용되더라도, 이 RD를 앞에 붙여 **고유한 주소**로 만들어 중복을 방지합니다. (예: `65000:1:192.168.1.0/24`)
    

#### **6-1-2. RT(Route Target)**

- **역할**: 경로의 **Export(경로 내보내기)** 및 **Import(경로 가져오기)** 정책을 정의하는 태그입니다.
    
- **이유**: 현재는 `both`를 사용하여 RD와 RT를 동일하게 설정함으로써, 같은 VRF_AI끼리만 경로를 주고받고, 다른 VRF(BIO, HPC)와는 통신이 차단되도록 논리적 분리를 구현합니다.
    

### **6-2. PE1 VRF 생성 실습**

PE1 라우터에 3개 연구그룹의 VRF를 생성합니다.

1. **전역 설정 모드 진입**
    
    Bash
    
    ```
    PE1> enable
    PE1# configure terminal
    ```
    
2. **VRF_AI 생성**
    
    Bash
    
    ```
    PE1(config)# vrf definition VRF_AI
    ```
    
    - `vrf definition VRF_AI`: VRF 컨테이너를 정의합니다.
        
    
    Bash
    
    ```
    PE1(config-vrf)# rd 65000:1
    ```
    
    - `rd 65000:1`: VRF_AI의 고유 식별자(RD)를 지정합니다.
        
    
    Bash
    
    ```
    PE1(config-vrf)# route-target both 65000:1
    ```
    
    - `route-target both 65000:1`: 이 VRF에 속한 경로를 `65000:1`로 **Export**하고, `65000:1` 태그가 붙은 경로만 **Import**하도록 설정하여 격리합니다.
        
    
    Bash
    
    ```
    PE1(config-vrf)# exit
    ```
    
3. **VRF_BIO 생성**
    
    Bash
    
    ```
    PE1(config)# vrf definition VRF_BIO
    PE1(config-vrf)# rd 65000:2
    PE1(config-vrf)# route-target both 65000:2
    PE1(config-vrf)# exit
    ```
    
4. **VRF_HPC 생성**
    
    Bash
    
    ```
    PE1(config)# vrf definition VRF_HPC
    PE1(config-vrf)# rd 65000:3
    PE1(config-vrf)# route-target both 65000:3
    PE1(config-vrf)# exit
    ```
    
5. **설정 저장**
    
    Bash
    
    ```
    PE1(config)# end
    PE1# write memory
    ```

## **7. DC 내부 연결: CE(Leaf) 라우터의 VRF 귀속**

### **7-0. 단계의 목표 및 중요성**

이 단계의 목표는 **Leaf 라우터(CE 역할)** 를  **PE 라우터**에 정의된 특정 **VRF**에 논리적으로 소속시켜, 연구 그룹별로 완전히 분리된 통신 환경을 구축하는 것입니다. 이로써 네트워크는 단순한 연습용을 넘어 **실제 기관 내부 정책망**의 정체성을 갖게 됩니다.

> **용어 정리: PE vs CE**
> 
> - **PE (Provider Edge)**: 중앙 라우터로, **VRF 컨테이너**를 실제로 들고 있는 장비입니다.
>     
> - **CE (Customer Edge/Leaf)**: 각 연구 그룹의 입구 라우터로, **VRF를 모른 채** PE에 연결만 합니다.
>     

|**Leaf**|**소속 연구 그룹**|**VRF**|**역할**|
|---|---|---|---|
|**Leaf1**|AI 연구실|`VRF_AI`|**VRF_AI**로 들어가는 입구|
|**Leaf2**|BIO 연구실|`VRF_BIO`|**VRF_BIO**로 들어가는 입구|
|**Leaf3**|HPC 연구실|`VRF_HPC`|**VRF_HPC**로 들어가는 입구|
|**Leaf4**|AI 연구실|`VRF_AI`|**VRF_AI**의 이중화 경로|

### **7-1. PE1에서 Leaf1 연결 (VRF_AI 귀속)**

Leaf1을 PE1의 인터페이스 Gi0/1에 연결하고, 이를 `VRF_AI`에 귀속시킵니다.

#### **7-1-1. PE1 인터페이스 VRF에 귀속**

**PE1** 라우터의 `Gi0/1` 인터페이스를 **`VRF_AI`** 전용 링크로 만듭니다.

Bash

```
PE1# configure terminal

PE1(config)# interface gigabitEthernet0/1
```

- **VRF 귀속 명령어**
    
    Bash
    
    ```
    PE1(config-if)# vrf forwarding VRF_AI
    ```
    
    - `vrf forwarding VRF_AI`: 이 순간, 인터페이스는 **`VRF_AI`**의 논리적 세계로 이동하고, **Global Routing Table**에서 분리됩니다.
        
    - **⚠️ 핵심 주의 사항**: 이 명령을 실행하는 순간, 해당 인터페이스에 설정되어 있던 **기존 IP 주소가 자동으로 삭제됩니다.** (이것이 앞서 ping이 실패한 원인입니다.)
        
- **IP 주소 재설정**
    
    Bash
    
    ```
    PE1(config-if)# ip address 172.16.1.1 255.255.255.0
    ```
    
    - **필수 재설정**: IP 주소를 다시 입력하여 VRF_AI 라우팅 테이블에 Connected 경로가 생기도록 합니다.
        
    
    Bash
    
    ```
    PE1(config-if)# no shutdown
    PE1(config-if)# exit
    ```
    

#### **7-1-2. VRF의 IPv4 라우팅 활성화 (핵심 해결책)**

PE1의 **VRF_AI** 라우팅 테이블이 정상적으로 생성되도록 명시적으로 **IPv4 Address-Family**를 활성화합니다.

Bash

```
PE1(config)# vrf definition VRF_AI
PE1(config-vrf)# address-family ipv4
PE1(config-vrf-af)# exit
PE1(config-vrf)# exit

PE1(config)# end
PE1# write memory
```

- `address-family ipv4`: 이 명령으로 **VRF_AI** 컨테이너 내부에서 **IPv4 라우팅 프로세스**가 실제로 활성화됩니다. (이것이 앞서 `show ip route vrf VRF_AI` 명령에서 테이블이 안 보이던 두 번째 원인이었습니다.)
    

### **7-2. Leaf1(CE) 설정**

Leaf1은 VRF의 존재를 모르며, PE1을 게이트웨이로만 인식합니다.

1. **기본 설정 및 호스트네임**
    
    Bash
    
    ```
    Router> enable
    Router# configure terminal
    Router(config)# hostname Leaf1
    Leaf1(config)# no ip domain-lookup
    ```
    
2. **PE1 연결 인터페이스 설정**
    
    Bash
    
    ```
    Leaf1(config)# interface gigabitEthernet0/0
    Leaf1(config-if)# ip address 172.16.1.2 255.255.255.0
    Leaf1(config-if)# no shutdown
    Leaf1(config-if)# exit
    ```
    
3. Default Gateway 설정
    
    (Leaf1은 모든 트래픽을 PE1(172.16.1.1)로 보냅니다.)
    
    Bash
    
    ```
    Leaf1(config)# ip route 0.0.0.0 0.0.0.0 172.16.1.1
    Leaf1(config)# end
    Leaf1# write memory
    ```
    

### **7-3. 설정 검증 (Leaf1 ↔ PE1)**

1. PE1에서 Connected 경로 확인
    
    (PE1이 Gi0/1에 설정된 172.16.1.0/24 네트워크를 VRF_AI 테이블에 보유해야 합니다.)
    
    Bash
    
    ```
    PE1# show ip route vrf VRF_AI
    ```
    
    - **기대 출력**: `C 172.16.1.0/24 is directly connected, GigabitEthernet0/1` 경로가 보여야 합니다.
        
2. Leaf1에서 통신 확인
    
    (PE1의 VRF_AI 인터페이스 IP로 통신을 시도합니다.)
    
    Bash
    
    ```
    Leaf1# ping 172.16.1.1
    ```
    
    - **기대 결과**: `!!!!!`로 성공해야 정상입니다.
        

컨설턴트로서 사용자님께서 앞선 까다로운 VRF 문제를 성공적으로 해결하시고 이제 복제 단계로 진입하신 것을 축하드립니다. 이제부터는 속도를 높여 **Leaf2, Leaf3, Leaf4**를 각각의 VRF에 귀속시키는 과정을 상세한 명령어와 설명으로 공식 문서 형식으로 정리해 드립니다.

## **8. DC 내부 연결: Leaf2, Leaf3, Leaf4 VRF 귀속**

Leaf1 설정 과정에서 얻은 핵심 지식(VRF 귀속 시 IP 재설정, `ip routing` 필수)을 바탕으로 나머지 Leaf 장비들을 각 연구그룹에 논리적으로 연결합니다.

### **8-1. Leaf2 → VRF_BIO 연결 (PE1)**

PE1의 Gi0/2 인터페이스를 통해 Leaf2(BIO 연구 그룹)를 `VRF_BIO`에 귀속시킵니다.

#### **8-1-1. PE1 인터페이스 설정 (Gi0/2)**

Bash

```
PE1# configure terminal
PE1(config)# interface gigabitEthernet0/2
// 1. Gi0/2를 VRF_BIO에 귀속. (이 순간 기존 IP는 삭제됨)
PE1(config-if)# vrf forwarding VRF_BIO 
// 2. IP 주소 재설정 (172.16.2.0/24 대역 사용)
PE1(config-if)# ip address 172.16.2.1 255.255.255.0
PE1(config-if)# no shutdown
PE1(config-if)# end
