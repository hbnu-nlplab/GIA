# 6.1 5대 네트워크 도메인 상세 설명 (초보자 가이드)

이 문서는 네트워크 지식이 없는 팀원들도 프로젝트의 5대 네트워크 도메인을 이해할 수 있도록 작성되었습니다. 각 네트워크의 목적, 핵심 개념, 실제 사용 사례를 중학생도 이해할 수 있는 수준으로 설명합니다.

---

## 1. Backbone (백본망) - "고속도로"

### 1.1 무엇인가?

**비유**: 백본망은 도시와 도시를 연결하는 **고속도로**입니다.

인터넷이나 회사 네트워크에서 데이터가 먼 거리를 빠르게 이동하려면 "큰 길"이 필요합니다. 백본망은 이런 큰 길 역할을 하는 네트워크입니다.

### 1.2 핵심 용어 설명

#### OSPF (Open Shortest Path First)

- **뜻**: "가장 짧은 길 먼저 찾기"
- **역할**: 라우터들이 서로 "어느 길이 가장 빠른가?"를 자동으로 찾아주는 프로토콜
- **비유**: 네비게이션이 실시간으로 최단 경로를 찾는 것과 같음

**예시**:

```
서울 → 부산 가는 길
- 경로 1: 경부고속도로 (400km, 4시간)
- 경로 2: 국도 (500km, 7시간)
→ OSPF는 자동으로 경로 1을 선택
```

#### IS-IS (Intermediate System to Intermediate System)

- **뜻**: "중간 시스템끼리 통신"
- **역할**: OSPF와 비슷하지만, 더 큰 네트워크에서 사용
- **차이점**: OSPF는 IP 주소 기반, IS-IS는 더 범용적

#### Fast Reroute (FRR)

- **뜻**: "빠른 우회"
- **역할**: 도로가 막히면 0.05초 안에 자동으로 다른 길로 우회
- **왜 중요한가?**: 전화 통화 중에 끊기면 안 되니까!

**예시**:

```
정상: 서울 → [경부고속도로] → 부산
고장: 경부고속도로 사고 발생!
FRR: 0.05초 안에 자동으로 → [중부고속도로] → 부산
```

### 1.3 실제 사용 사례

**VoIP (인터넷 전화)**:

- 카카오톡 음성통화, Zoom 회의
- 0.1초만 지연되어도 "뚝뚝" 끊김
- 백본망이 빠르게 우회하지 못하면 통화 품질 저하

**미션 크리티컬 서비스**:

- 은행 거래, 증권 거래
- 1초 지연 = 수억 원 손실 가능
- 백본망의 안정성이 생명

### 1.4 우리가 검증할 것

1. **링크 장애 시 복구 시간**: 50ms 이내에 우회하는가?
2. **경로 계산 정확성**: 항상 최단 경로를 선택하는가?
3. **부하 분산**: 여러 경로에 트래픽을 골고루 나누는가?

## 2. Metro/L2VPN (메트로망) - "전용 터널"

### 2.1 무엇인가?

**비유**: 메트로망은 회사 본사와 지사를 연결하는 **전용 지하철**입니다.

일반 인터넷(공용 도로)을 쓰지 않고, 회사만의 전용 통로를 만들어 줍니다.

### 2.2 핵심 용어 설명

#### L2 (Layer 2)

- **뜻**: "2층 네트워크"
- **역할**: MAC 주소(기기 고유 번호)로 통신
- **비유**: 같은 건물 안에서 방 번호로 찾아가기

#### VPWS (Virtual Private Wire Service)

- **뜻**: "가상 전용 전선"
- **역할**: 두 지점을 1:1로 연결 (마치 전용 케이블을 깔은 것처럼)
- **예시**: 서울 본사 ↔ 부산 지사 (전용선)

#### VPLS (Virtual Private LAN Service)

- **뜻**: "가상 전용 LAN"
- **역할**: 여러 지점을 하나의 네트워크처럼 연결
- **예시**: 서울, 부산, 대구 지사가 마치 같은 사무실처럼 통신

**차이점**:

```
VPWS (1:1 전용선):
서울 본사 ←────────→ 부산 지사

VPLS (다:다 네트워크):
    서울 본사
      ↙  ↓  ↘
  부산  대구  광주
```

#### QinQ (Q-in-Q)

- **뜻**: "태그 안에 태그"
- **역할**: VLAN 태그를 2개 붙여서 더 많은 고객을 구분
- **비유**: 우편번호(외부 태그) + 상세 주소(내부 태그)

**예시**:

```
외부 태그: 고객사 구분 (삼성=100, LG=200)
내부 태그: 부서 구분 (영업=10, 개발=20)
→ 삼성 영업부 = 100.10
```

### 2.3 실제 사용 사례

**기업 전용선**:

- 은행의 본점 ↔ 지점 연결
- 보안상 인터넷을 쓸 수 없음
- L2VPN으로 마치 같은 건물처럼 연결

**재해복구 센터**:

- 주 데이터센터 ↔ 백업 데이터센터
- 실시간 데이터 동기화 필요
- VPWS로 전용선처럼 연결

### 2.4 우리가 검증할 것

1. **VLAN 태깅 정확성**: 고객사 데이터가 섞이지 않는가?
2. **Pseudowire 연결**: 가상 전선이 끊기지 않는가?
3. **L2 투명성**: 본사와 지사가 정말 같은 네트워크처럼 보이는가?

## 3. ISP/L3VPN (클라우드 백본) - "아파트 단지"

### 3.1 무엇인가?

**비유**: L3VPN은 하나의 건물(ISP 망)에 여러 회사(고객)가 **완전히 격리된 사무실**을 쓰는 것입니다.

AWS, Azure 같은 클라우드가 바로 이 기술을 씁니다. 삼성과 LG가 같은 ISP 망을 쓰지만, 서로의 데이터는 절대 볼 수 없습니다.

### 3.2 핵심 용어 설명

#### VRF (Virtual Routing and Forwarding)

- **뜻**: "가상 라우팅 테이블"
- **역할**: 하나의 라우터 안에 여러 개의 독립된 라우팅 테이블 생성
- **비유**: 한 건물에 삼성 전용 엘리베이터, LG 전용 엘리베이터

**예시**:

```
라우터 PE1 안에:
- VRF Red (삼성 전용): 10.1.1.0/24 → 삼성 서버
- VRF Blue (LG 전용): 10.1.1.0/24 → LG 서버
→ 같은 IP 주소여도 완전히 다른 곳으로 감!
```

#### MP-BGP (Multi-Protocol BGP)

- **뜻**: "다중 프로토콜 BGP"
- **역할**: VRF 정보를 다른 라우터에게 알려주는 프로토콜
- **비유**: "삼성 고객은 빨간 엘리베이터 타세요"라고 안내방송

#### Route Target (RT)

- **뜻**: "라우팅 목표 태그"
- **역할**: 어떤 VRF에서 어떤 경로를 받을지 결정
- **비유**: 우편물에 붙이는 "삼성 전용" 스티커

**예시**:

```
PE1의 VRF Red:
- Export RT: 65000:100 (내보낼 때 이 태그 붙임)
- Import RT: 65000:100 (이 태그 있는 것만 받음)

PE2의 VRF Red:
- Import RT: 65000:100 (PE1이 보낸 것을 받음)
→ 삼성 네트워크 완성!
```

#### Route Reflector (RR)

- **뜻**: "경로 반사기"
- **역할**: 모든 PE가 서로 연결하지 않아도 되게 중계
- **비유**: 우체국 (모든 집이 서로 직접 우편 안 보내고 우체국 경유)

**왜 필요한가?**:

```
RR 없이:
PE1 ↔ PE2
PE1 ↔ PE3
PE1 ↔ PE4
PE2 ↔ PE3
PE2 ↔ PE4
PE3 ↔ PE4
→ 6개 연결 필요 (복잡!)

RR 사용:
PE1 → RR ← PE2
        ↑
PE3 ← RR → PE4
→ 4개 연결만 필요 (간단!)
```

### 3.3 실제 사용 사례

**AWS/Azure 클라우드**:

- 수천 개 고객사가 같은 물리 망 사용
- VRF로 완벽히 격리
- 고객 A는 고객 B의 데이터를 절대 볼 수 없음

**통신사 기업 서비스**:

- KT, SK가 제공하는 "기업 전용 인터넷"
- 일반 인터넷과 분리된 VRF
- 보안 강화

### 3.4 우리가 검증할 것

1. **VRF 격리**: 삼성 데이터가 LG로 새는가?
2. **RT 정확성**: Import/Export 태그가 정확한가?
3. **Route Reflector 동작**: RR이 죽으면 전체 망이 마비되는가?

## 4. Internet/BGP (인터넷 Edge) - "국경 검문소"

### 4.1 무엇인가?

**비유**: BGP는 나라와 나라 사이의 **국경 검문소**입니다.

인터넷은 수만 개의 ISP(나라)가 연결된 거대한 네트워크입니다. BGP는 "어느 나라를 거쳐 가는 게 빠른가?"를 결정합니다.

### 4.2 핵심 용어 설명

#### AS (Autonomous System)

- **뜻**: "자율 시스템" (= 독립 국가)
- **역할**: 인터넷을 구성하는 독립적인 네트워크 조직
- **예시**: KT = AS 4766, Google = AS 15169

#### eBGP (External BGP)

- **뜻**: "외부 BGP"
- **역할**: 서로 다른 AS 간 통신
- **비유**: 한국 ↔ 미국 외교

#### iBGP (Internal BGP)

- **뜻**: "내부 BGP"
- **역할**: 같은 AS 내부 통신
- **비유**: 서울 ↔ 부산 (같은 나라 안)

#### AS-Path

- **뜻**: "AS 경로"
- **역할**: 데이터가 거쳐온 AS 목록
- **비유**: 여권 스탬프 (한국 → 일본 → 미국)

**예시**:

```
구글(AS 15169)에 가는 경로:
경로 1: 내 AS → KT(AS 4766) → Google
경로 2: 내 AS → SK(AS 9318) → NTT(AS 2914) → Google
→ 경로 1이 더 짧으니까 선택!
```

#### Local Preference

- **뜻**: "로컬 선호도"
- **역할**: 같은 목적지에 여러 경로가 있을 때 우선순위 결정
- **비유**: "KT가 SK보다 빠르니까 KT 우선!"

**예시**:

```
구글 가는 길:
- KT 경유: Local Pref = 200 (높음)
- SK 경유: Local Pref = 100 (낮음)
→ 숫자 큰 KT 선택!
```

#### MED (Multi-Exit Discriminator)

- **뜻**: "다중 출구 판별자"
- **역할**: 상대방에게 "이 출구로 들어오세요" 힌트 주기
- **비유**: "서울역보다 강남역이 더 가까워요"

### 4.3 실제 사용 사례

**멀티호밍 (Multihoming)**:

- 회사가 KT, SK 두 회선 동시 사용
- KT 장애 시 자동으로 SK로 전환
- BGP로 자동 경로 변경

**트래픽 엔지니어링**:

- "미국 트래픽은 KT로, 중국 트래픽은 SK로"
- BGP Policy로 제어

### 4.4 우리가 검증할 것

1. **경로 선택 정확성**: 항상 최적 경로를 선택하는가?
2. **Failover 속도**: ISP 하나 죽으면 얼마나 빨리 전환되는가?
3. **Policy 적용**: Local Pref, MED가 제대로 작동하는가?

## 5. Advanced/Multicast (차세대 망) - "방송국"

### 5.1 무엇인가?

**비유**: 멀티캐스트는 **TV 방송국**입니다.

일반 통신(Unicast)은 1:1 전화 통화입니다. 멀티캐스트는 1:다수 방송입니다. IPTV, 온라인 강의가 바로 이 기술을 씁니다.

### 5.2 핵심 용어 설명

#### Unicast vs Multicast

- **Unicast (1:1)**: 선생님이 학생 한 명씩 개별 통화
- **Multicast (1:다수)**: 선생님이 확성기로 전체 방송

**대역폭 비교**:

```
100명에게 영상 전송 (10Mbps 영상)

Unicast:
서버 → 학생1 (10Mbps)
서버 → 학생2 (10Mbps)
...
서버 → 학생100 (10Mbps)
→ 총 1,000Mbps 필요! (서버 과부하)

Multicast:
서버 → 네트워크 (10Mbps 한 번만)
→ 네트워크가 알아서 100명에게 복사
→ 총 10Mbps만 필요! (효율적)
```

#### Multicast Group

- **뜻**: "방송 채널"
- **주소**: 239.x.x.x (특수 IP 주소)
- **비유**: TV 채널 번호 (MBC = 11번, KBS = 9번)

**예시**:

```
239.1.1.1 = 뉴스 채널
239.1.1.2 = 드라마 채널
239.1.1.3 = 스포츠 채널
```

#### IGMP (Internet Group Management Protocol)

- **뜻**: "인터넷 그룹 관리 프로토콜"
- **역할**: "저 239.1.1.1 채널 보고 싶어요!" 신청
- **비유**: TV 셋톱박스에서 채널 선택

**동작 과정**:

```
1. 사용자: "239.1.1.1 보고 싶어요" (IGMP Join)
2. 라우터: "알겠습니다, 연결해드릴게요"
3. 영상 수신 시작
4. 사용자: "이제 안 볼래요" (IGMP Leave)
5. 라우터: "연결 끊을게요"
```

#### PIM-SM (Protocol Independent Multicast - Sparse Mode)

- **뜻**: "희소 모드 멀티캐스트 프로토콜"
- **역할**: 라우터들이 멀티캐스트 트리를 만드는 방법
- **Sparse Mode**: "보고 싶은 사람만 신청" (효율적)

#### RP (Rendezvous Point)

- **뜻**: "만남의 장소"
- **역할**: 송신자와 수신자를 연결해주는 중계 라우터
- **비유**: 방송국 중계소

**동작 과정**:

```
1. 송신자(Video Server): "239.1.1.1로 방송 시작!" → RP에게 알림
2. 수신자(셋톱박스): "239.1.1.1 보고 싶어요!" → RP에게 신청
3. RP: "송신자와 수신자 연결해드릴게요"
4. 멀티캐스트 트리 형성 → 영상 전송 시작
```

#### Anycast RP

- **뜻**: "여러 개의 RP를 하나처럼"
- **역할**: RP가 죽어도 다른 RP가 자동 대체
- **비유**: 방송국이 2개 있어서 하나 고장 나도 OK

### 5.3 실제 사용 사례

**IPTV (인터넷 TV)**:

- KT 올레TV, SK Btv
- 수백만 명이 동시에 같은 채널 시청
- 멀티캐스트 없으면 서버 폭발

**온라인 강의**:

- Zoom 웨비나 (1,000명 동시 접속)
- 멀티캐스트로 효율적 전송

**주식 시세 전송**:

- 증권사가 실시간 시세를 수천 명에게 전송
- 멀티캐스트로 지연 최소화

### 5.4 우리가 검증할 것

1. **RP 동작**: RP가 죽으면 방송이 끊기는가?
2. **IGMP 처리**: 사용자가 채널 바꾸면 즉시 반영되는가?
3. **Multicast Tree**: 최적 경로로 트리가 형성되는가?
4. **MTU 문제**: 큰 패킷이 잘 전송되는가?

| **Internet/BGP** | 국경 검문소 | AS-Path, Policy | ISP 연동     |
| **Multicast**    | 방송국      | PIM-SM, RP      | IPTV, 웨비나 |
