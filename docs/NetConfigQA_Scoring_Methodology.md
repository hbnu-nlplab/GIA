# NetConfigQA: Type-Aware Scoring Methodology

**문서 정보**

- **대상**: AI 및 네트워크 연구실 연구원 및 관련 이해관계자
- **목적**: 네트워크 설정 자동 질의응답(NetConfigQA) 시스템의 평가 신뢰도 향상을 위한 데이터 타입별 채점 방식 정의
- **작성일**: 2025-12-27

---

## 1. 개요 (Overview)

본 문서는 **NetConfigQA** 데이터셋의 평가를 위해 설계된 **Type-Aware Scoring** 프레임워크를 설명합니다. 기존의 일반적인 자연어 처리(NLP) 평가지표는 네트워크 구성 요소의 구조적 특성을 반영하지 못한다는 한계가 있습니다. 이를 해결하기 위해 정답의 데이터 타입(Boolean, Numeric, Set, Map, Text)에 따라 최적화된 비교 로직을 적용하여 실제 성능을 정확하게 측정합니다.

## 2. 기존 지표의 한계 및 비교 (Analysis of Metrics)

네트워크 설정 정보는 엄격한 데이터 규격을 따르기 때문에, 단순히 텍스트 간의 유사도를 측정하는 방식은 실제 모델의 성능을 왜곡할 수 있습니다.

### 2.1 주요 평가지표 비교

| 평가지표             | 비교 방식                  | 네트워크 도메인 적용 시 문제점                                        |
| :------------------- | :------------------------- | :-------------------------------------------------------------------- |
| **Exact Match (EM)** | 문자열 완전 일치           | 대소문자, 공백, 따옴표 차이 등 사소한 포맷 이슈로도 0점 처리됨.       |
| **Token F1 Score**   | 단어(Token) 일치율         | 리스트 데이터(`Set`)의 순서가 바뀌면 오답으로 처리됨.                 |
| **BERTScore F1**     | 벡터 공간 내 유사도        | **`Gi0/1`과 `Gi0/2`를 유사한 단어로 오판**하여 할루시네이션을 허용함. |
| **Type-Aware (Our)** | **데이터 속성(Type) 비교** | 각 답변의 데이터 성격에 맞춰 **정확성과 유연성을 동시에 확보**함.     |

### 2.2 차별점: "텍스트"가 아닌 "데이터"로의 접근

기존 지표들은 답변을 단순히 '글자 뭉치'로 보지만, **Type-Aware 채점**은 답변을 **의미를 가진 데이터 타입**으로 해석합니다.

- **Set Type**: 순서가 중요한 '문장'이 아니라, 순서가 없는 '목록'으로 취급하여 순서 변경에 관대합니다.
- **Numeric Type**: `1`과 `1.0`을 글자가 아닌 '값(Value)'으로 비교하여 수학적 동등성을 인정합니다.
- **Symbolic Match**: 인터페이스 이름 등은 철자가 하나만 틀려도 완전히 다른 장치이므로, BERTScore와 같은 '유사도' 방식을 배제하고 엄격한 1:1 매칭을 적용합니다.

## 3. Type-Aware Scoring 핵심 메커니즘

각 데이터 타입별로 전처리(Cleaning)와 비교(Matching) 단계를 거쳐 최종 점수(Score, 0.0~1.0)를 산출합니다.

### 3.1 Boolean Type (참/거짓)

- **로직**: 대소문자 무관 비교 및 동의어(Yes/No, Enabled/Disabled) 처리.
- **예시 (ID 112)**: `p3` 장비 SSH 활성화 여부
  - Gold: `true` / Pred: `yes` → **1.0 Score**

### 3.2 Numeric Type (숫자)

- **로직**: 단위(명, 개) 등 텍스트 제거 후 정수/실수 값 비교.
- **예시 (ID 42)**: `p4` 장비 로컬 사용자 수
  - Gold: `1` / Pred: `1.0명` → **1.0 Score**

### 3.3 Set Type (집합)

- **로직**: 순서에 상관없이 요소의 일치도를 측정하기 위해 **F1 Score**를 리스트 단위로 적용.
- **예시 (ID 271)**: `p1` 장비 OSPF Area 0 인터페이스
  - Gold: `["Gi0/0", "Gi0/1", "Lo0"]`
  - Pred: `["Lo0", "Gi0/1"]` → **0.8 Score** (F1 계산 적용)

### 3.4 Map Type (구조적 데이터)

- **로직**: Key와 Value를 각각 평가하는 하이브리드 로직(Common Key % + Value Match %).
- **예시 (ID 92)**: `leaf4` 인터페이스 상태 맵
  - Gold: `{"Gi0/0": "up", "Gi0/1": "down"}`
  - Pred: `{"Gi0/0": "up"}` → (키 일치 0.5 + 값 일치 1.0) 기반의 가중 합산.

### 3.5 Text Type (일반 텍스트)

- **로직**: 호스트네임이나 버전 정보 등. Trim 및 소문자 변환 후 비교.

## 4. 부정 테스트 및 할루시네이션 방지 (Negative Testing)

데이터셋에는 의도적으로 설정되지 않은 정보에 대한 질문이 포함되어 있습니다.

- **Metric ID 22**: `p4` 장비의 타임존
  - Gold: `null` (설정 없음)
  - 모델이 `UTC` 등 허위 정보를 생성할 경우 **0.0점** 처리하여 할루시네이션을 엄격히 탐지합니다.

## 5. 기대 효과 (Expected Impact)

1. **평가 신뢰도 확보**: 모델의 사소한 포맷 실수(대소문자, 공백)를 배제하고 실제 네트워크 지식 수준을 평가합니다.
2. **벤치마크 일관성**: 서로 다른 크기와 특성의 LLM(Qwen, Mistral 등)을 동일한 잣대로 객관적 비교가 가능합니다.
3. **연구 논문 근거**: Type-Aware 방식의 학술적 타당성을 통해 시스템 성능 보고의 전문성을 높입니다.
