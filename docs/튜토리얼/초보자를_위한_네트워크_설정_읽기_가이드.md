## 1. 기초 개념: 네트워크 장비 설정 파일이란?

### 1.1 설정 파일의 정의
네트워크 라우터, 스위치, 방화벽 등의 장비는 **설정 파일(Configuration File, `.cfg`)**을 가지고 있습니다. 이 파일은 다음 질문들에 대한 답변서입니다:
*   장비의 이름이 뭐야? → `hostname`
*   어떤 선이 연결되어 있어? → `interface`
*   데이터를 어디로 보낼까? → `router ospf`, `router bgp`
*   고객사별로 네트워크를 어떻게 분리해? → `vrf definition`
*   누가 접속할 수 있어? → `username`, `line vty`

### 1.2 설정 파일의 형식
Cisco IOS 설정 파일은 **계층 구조**를 따릅니다:
```
명령어
 부명령어 (들여쓰기 1칸)
  하위 부명령어 (들여쓰기 2칸)
   ...
```

예를 들어:
```properties
interface GigabitEthernet0/0          <- 인터페이스 시작
 ip address 10.0.1.1 255.255.255.254 <- 이 인터페이스의 IP 설정
 duplex auto                          <- 이 인터페이스의 속도 설정
 media-type rj45                      <- 이 인터페이스의 포트 타입
```

## 2. PE1.cfg 전체 구조 분석

`PE1.cfg` 파일은 다음과 같이 구성되어 있습니다:

### 2.1 파일 맨 위 (글로벌 설정)
```properties
version 15.7                          <- OS 버전
hostname PE1                          <- 장비 이름
username admin privilege 15 secret ... <- 접속 계정
ip ssh version 2                      <- SSH 버전
```

### 2.2 가상 라우팅 공간 정의 (VRF)
```properties
vrf definition VRF_AI                 <- 고객사 A를 위한 독립 라우팅 공간
 rd 65000:1                           <- 이 VRF의 고유 ID
 route-target export 65000:1          <- 다른 VRF에게 경로를 줄 때 붙일 태그
 route-target import 65000:1          <- 다른 VRF로부터 받을 경로 태그
```

### 2.3 물리 인터페이스 정의
```properties
interface Loopback0                   <- 가상 인터페이스 (항상 켜져있음)
 ip address 10.255.0.11 255.255.255.255

interface GigabitEthernet0/0          <- 실제 네트워크 카드 포트
 ip address 10.0.1.1 255.255.255.254 <- 이 선의 IP 주소

interface GigabitEthernet0/1          <- VRF에 속한 포트
 vrf forwarding VRF_AI                <- 이 포트는 VRF_AI에만 속함!
 ip address 172.16.1.1 255.255.255.0
```

### 2.4 라우팅 프로토콜 설정
```properties
router ospf 1                         <- OSPF로 길 찾기를 시작
 network 10.0.1.0 0.0.0.255 area 0   <- 이 범위의 인터페이스를 Area 0에 등록

router bgp 65000                      <- BGP로 다른 회사와 통신
 neighbor 10.255.0.12 remote-as 65000 <- 옆 장비(PE2)의 이웃 설정
```

## 3. [L1] 단일 장비 정보 찾기 (기초)

### 📌 Q1. "{host} 장비의 호스트네임은 무엇입니까?"

**[정보 분류]**: System Inventory (기본 정보 조회)

**[찾는 방법]**:
파일을 열고 맨 위에서 `hostname` 키워드를 검색합니다. (Ctrl+F로 검색!)

**[PE1.cfg 의 실제 모습]**:
```properties
!
! Last configuration change at 15:16:31 UTC Wed Dec 17 2025
!
version 15.7
service timestamps debug datetime msec
service timestamps log datetime msec
no service password-encryption
!
hostname PE1                    ← 여기!
!
boot-start-marker
boot-end-marker
```

**[정답 찾기]**: `hostname` 뒤의 단어 = **PE1**

**[왜 중요한가?]**: 
관리자가 수십 대의 장비를 관리할 때, 로그에서 "PE1에서 오류 발생" 하는 메시지를 보면, 이 hostname이 일치하는지 먼저 확인합니다. 만약 호스트네임이 `Router_1`이라고 설정되어 있으면, 다른 사람은 이 장비가 PE1이 아닌 줄 알 수 있습니다.

---

### 📌 Q2. "{host} 장비의 운영체제(OS) 버전은 무엇입니까?"

**[정보 분류]**: System Inventory (장비 스펙)

**[찾는 방법]**:
파일 상단에서 `version` 뒤의 숫자를 찾습니다.

**[PE1.cfg 의 실제 모습]**:
```properties
version 15.7
service timestamps debug datetime msec
```

**[정답 찾기]**: `version` 뒤의 숫자 = **15.7**

**[읽는 방법 - 버전 번호 해석]**:
*   `15.7`: Cisco IOS 버전 15, 마이너 버전 7
*   `15.2(4)M3`: 더 복잡한 버전(15.2 베이스, 4번째 업데이트, M3 브랜치)
*   버전이 낮을수록 오래된 OS, 버전이 높을수록 최신 OS

**[왜 중요한가?]**: 
보안 취약점이나 버그가 버전마다 다르므로, OS 버전을 먼저 파악해야 보안 패치 계획을 세울 수 있습니다.

---

### 📌 Q3. "{host} 장비에 등록된 로컬 사용자 목록을 알려주세요."

**[정보 분류]**: Security Inventory (접근 제어)

**[찾는 방법]**:
`username`으로 시작하는 모든 라인을 찾아 사용자명을 추출합니다.

**[PE1.cfg 의 실제 모습]**:
```properties
username admin privilege 15 secret 5 $1$1TT7$6NEugkkWBy.AzeNfZi61A1
```

**[정답 찾기]**: 
*   라인 분석: `username` + `admin` + `privilege 15` + `secret ...`
*   사용자명 추출: **admin** (나머지는 권한 설정)
*   정답: **['admin']**

**[상세 분석]**:
*   `privilege 15`: 관리자 권한 (최고 권한은 15)
*   `secret 5`: MD5 암호화로 저장됨 (현대에는 너무 약함)
*   비밀번호 부분: `$1$1TT7$...` (실제 비번은 숨겨짐)

**[PE1.cfg에서 사용자가 1명뿐이 이유]**:
일반적으로 대규모 네트워크에서는 로컬 사용자 대신 **TACACS+** 또는 **RADIUS** 같은 중앙 인증 서버를 사용합니다. 여긴 긴급 접속용 백업 계정만 있는 것입니다.

---

### 📌 Q4. "{host} 장비의 시간대(Timezone)는 무엇입니까?"

**[찾는 방법]**:
`clock timezone` 명령을 검색합니다.

**[PE1.cfg 의 현황]**:
```properties
(검색 결과: 찾을 수 없음)
```

**[정답 찾기]**: 설정이 없으므로 → **UTC (기본값)**

**[왜 설정이 안 되어 있나?]**:
대규모 네트워크에서는 모든 장비를 UTC 기준으로 설정하여 시간 혼동을 없앱니다. 그래서 Korea Time (KST)를 설정할 이유가 없습니다.

## 4. 와일드카드 마스크 완전 이해

이 부분은 **매우 중요**합니다. OSPF, BGP, ACL 등 거의 모든 설정에서 와일드카드 마스크가 나옵니다.

### 4.1 와일드카드 마스크가 뭐예요?

**간단히 말해서**: "어떤 부분은 정확하게 맞춰야 하고, 어떤 부분은 아무거나 상관없다"는 뜻입니다.

*   `0` = 정확하게 일치해야 함
*   `255` = 아무거나 상관 안 함

### 4.2 실제 예제로 배우기

#### 예제 1: `10.0.1.0 0.0.0.255`

**[분석]**:
```
IP:      10 . 0  . 1  . 0
Mask:     0 . 0  . 0  . 255
결과:    정확 정확 정확 상관없음
```

**[의미]**: "IP의 앞 세 자리가 `10.0.1.`로 시작하면, 마지막 자리는 뭐든 상관없다"

**[포함되는 IP들]**:
*   ✅ `10.0.1.0` (포함)
*   ✅ `10.0.1.1` (포함)
*   ✅ `10.0.1.254` (포함)
*   ✅ `10.0.1.255` (포함)
*   ❌ `10.0.2.0` (불포함 - 3번째 자리가 다름)
*   ❌ `10.1.1.1` (불포함 - 2번째 자리가 다름)

#### 예제 2: `10.255.0.11 0.0.0.0`

**[분석]**:
```
IP:      10 . 255 . 0  . 11
Mask:     0 .   0  . 0  .  0
결과:    정확 정확 정확 정확
```

**[의미]**: "정확히 `10.255.0.11`이어야만 한다"

**[포함되는 IP들]**:
*   ✅ `10.255.0.11` (정확하게 일치)
*   ❌ `10.255.0.12` (마지막 자리가 다름)
*   ❌ `10.255.0.10` (마지막 자리가 다름)

### 4.3 PE1.cfg의 OSPF 설정에 적용하기

PE1의 OSPF 설정을 봅시다:
```properties
router ospf 1
 router-id 10.255.0.11
 network 10.0.1.0 0.0.0.255 area 0
 network 10.255.0.11 0.0.0.0 area 0
 network 10.255.0.0 0.0.0.255 area 0
```

**[해석]**:
1️⃣ `network 10.0.1.0 0.0.0.255 area 0`
   *   범위: `10.0.1.x` (0~255)
   *   포함되는 인터페이스: `GigabitEthernet0/0` (IP: 10.0.1.1) ✅

2️⃣ `network 10.255.0.11 0.0.0.0 area 0`
   *   범위: 정확히 `10.255.0.11`만
   *   포함되는 인터페이스: `Loopback0` (IP: 10.255.0.11) ✅

3️⃣ `network 10.255.0.0 0.0.0.255 area 0`
   *   범위: `10.255.0.x` (0~255)
   *   포함되는 인터페이스: `Loopback0` (IP: 10.255.0.11) ✅

**[중요 발견]**: Loopback0은 2번과 3번 범위에 **모두 포함**됩니다! 하지만 인터페이스는 하나이므로, 최종 답은 **중복 제거** 후 반환합니다.

## 5. [L1] 인터페이스 정보 찾기 (중급)

### 📌 Q5. "{host} 장비의 각 인터페이스에 할당된 IP 주소를 알려주세요."

**[정보 분류]**: Interface Inventory (포트별 IP 현황)

**[찾는 방법]**:
모든 `interface` 블록을 찾아 `ip address` 값을 수집합니다.

**[PE1.cfg 의 실제 구조]**:
```properties
interface Loopback0
 ip address 10.255.0.11 255.255.255.255
!
interface GigabitEthernet0/0
 ip address 10.0.1.1 255.255.255.254
 duplex auto
 speed auto
 media-type rj45
 mpls ip
!
interface GigabitEthernet0/1
 vrf forwarding VRF_AI
 ip address 172.16.1.1 255.255.255.0
!
interface GigabitEthernet0/2
 vrf forwarding VRF_BIO
 ip address 172.16.2.1 255.255.255.0
!
interface GigabitEthernet0/3
 ip address 10.10.10.21 255.255.255.0
```

**[수집 단계]**:
1.  Loopback0: `10.255.0.11 255.255.255.255`
2.  GigabitEthernet0/0: `10.0.1.1 255.255.255.254`
3.  GigabitEthernet0/1: `172.16.1.1 255.255.255.0`
4.  GigabitEthernet0/2: `172.16.2.1 255.255.255.0`
5.  GigabitEthernet0/3: `10.10.10.21 255.255.255.0`

**[CIDR 표기법으로 변환]**:

| 인터페이스 | IP | 서브넷 마스크 | CIDR 표기 | 설명 |
|:---|:---|:---|:---|:---|
| Loopback0 | 10.255.0.11 | 255.255.255.255 | /32 | 단일 호스트 (Loopback용) |
| Gi0/0 | 10.0.1.1 | 255.255.255.254 | /31 | Point-to-Point 링크 (2개 호스트만) |
| Gi0/1 | 172.16.1.1 | 255.255.255.0 | /24 | 일반 서브넷 (256개 호스트) |
| Gi0/2 | 172.16.2.1 | 255.255.255.0 | /24 | 일반 서브넷 (256개 호스트) |
| Gi0/3 | 10.10.10.21 | 255.255.255.0 | /24 | 일반 서브넷 (256개 호스트) |

**[정답]**:
```json
{
  "Loopback0": "10.255.0.11/32",
  "GigabitEthernet0/0": "10.0.1.1/31",
  "GigabitEthernet0/1": "172.16.1.1/24",
  "GigabitEthernet0/2": "172.16.2.1/24",
  "GigabitEthernet0/3": "10.10.10.21/24"
}
```

### 📌 Q6. "{host} 장비의 각 인터페이스 상태는 어떻게 됩니까?"

**[찾는 방법]**:
각 `interface` 블록에서 `shutdown` 명령 여부를 확인합니다.

**[규칙]**:
*   `shutdown` 명령이 있으면 → **down** (꺼져있음)
*   `shutdown` 명령이 없으면 → **up** (켜져있음)
*   `no shutdown` 명령이 있으면 → **up** (명시적으로 켜짐)

**[PE1.cfg 분석]**:
```properties
interface Loopback0
 ip address 10.255.0.11 255.255.255.255
 (shutdown 명령 없음) → UP

interface GigabitEthernet0/0
 ip address 10.0.1.1 255.255.255.254
 (shutdown 명령 없음) → UP

interface GigabitEthernet0/1
 vrf forwarding VRF_AI
 ip address 172.16.1.1 255.255.255.0
 (shutdown 명령 없음) → UP

(모든 인터페이스에 shutdown이 없음)
```

**[정답]**:
```json
{
  "Loopback0": "up",
  "GigabitEthernet0/0": "up",
  "GigabitEthernet0/1": "up",
  "GigabitEthernet0/2": "up",
  "GigabitEthernet0/3": "up"
}
```

## 6. [L1] OSPF 라우팅 정보 (고급)

### 📌 Q8. "{host} 장비의 OSPF Area 0에 연결된 인터페이스 목록을 알려주세요."

**이것이 가장 어려운 질문입니다!** 앞서 배운 와일드카드 마스크를 여기서 사용합니다.

**[정보 분류]**: Routing Inventory (OSPF 토폴로지)

**[단계별 분석]**:

**[Step 1] OSPF 섹션 찾기**:
```properties
router ospf 1
 router-id 10.255.0.11
 network 10.0.1.0 0.0.0.255 area 0      ← Area 0 설정 1
 network 10.255.0.11 0.0.0.0 area 0     ← Area 0 설정 2
 network 10.255.0.0 0.0.0.255 area 0    ← Area 0 설정 3
```

**[Step 2] 각 network 범위 계산하기**:

**범위 1**: `10.0.1.0 0.0.0.255`
```
IP:        10.0.1.0
Wildcard:  0.0.0.255
범위:     10.0.1.0 ~ 10.0.1.255
```

**범위 2**: `10.255.0.11 0.0.0.0`
```
IP:        10.255.0.11
Wildcard:  0.0.0.0
범위:     정확히 10.255.0.11만
```

**범위 3**: `10.255.0.0 0.0.0.255`
```
IP:        10.255.0.0
Wildcard:  0.0.0.255
범위:     10.255.0.0 ~ 10.255.0.255
```

**[Step 3] 인터페이스 IP와 매칭하기**:

| 인터페이스 | IP | 범위1 | 범위2 | 범위3 | 결과 |
|:---|:---|:---:|:---:|:---:|:---|
| Loopback0 | 10.255.0.11 | ❌ | ✅ | ✅ | Area 0 포함 |
| Gi0/0 | 10.0.1.1 | ✅ | ❌ | ❌ | Area 0 포함 |
| Gi0/1 | 172.16.1.1 | ❌ | ❌ | ❌ | Area 0 미포함 |
| Gi0/2 | 172.16.2.1 | ❌ | ❌ | ❌ | Area 0 미포함 |
| Gi0/3 | 10.10.10.21 | ❌ | ❌ | ❌ | Area 0 미포함 |

**[정답]**: **['Loopback0', 'GigabitEthernet0/0']**

## 7. [L1] VRF 및 BGP 정보 (고급)

### 📌 Q11. "{host} 장비에 설정된 VRF 이름 목록을 알려주세요."

**[정보 분류]**: Services Inventory (가상 네트워크 분할)

**[찾는 방법]**:
`vrf definition` 뒤의 이름을 모두 수집합니다.

**[PE1.cfg 의 실제 구조]**:
```properties
vrf definition VRF_AI
 rd 65000:1
 route-target export 65000:1
 route-target import 65000:1
 !
 address-family ipv4
 exit-address-family
!
vrf definition VRF_BIO
 rd 65000:2
 route-target export 65000:2
 route-target import 65000:2
 !
 address-family ipv4
 exit-address-family
!
vrf definition VRF_HPC
 rd 65000:3
 route-target export 65000:3
 route-target import 65000:3
 !
 address-family ipv4
 exit-address-family
```

**[VRF의 의미]**:
*   **VRF_AI**: 인공지능 연구용 고객 네트워크 (RD: 65000:1)
*   **VRF_BIO**: 바이오 연구용 고객 네트워크 (RD: 65000:2)
*   **VRF_HPC**: 고성능 컴퓨팅용 고객 네트워크 (RD: 65000:3)

**[정답]**: **['VRF_AI', 'VRF_BIO', 'VRF_HPC']**

---

### 📌 Q12. "{host} 장비의 VRF 개수는?"

**[정답]**: **3개**

---

### 📌 Q13. "{host} 장비의 각 VRF별 RD(Route Distinguisher)는?"

**[찾는 방법]**:
각 `vrf definition` 블록 내에서 `rd` 값을 추출합니다.

**[PE1.cfg 분석]**:
```properties
vrf definition VRF_AI
 rd 65000:1              ← VRF_AI의 RD는 65000:1

vrf definition VRF_BIO
 rd 65000:2              ← VRF_BIO의 RD는 65000:2

vrf definition VRF_HPC
 rd 65000:3              ← VRF_HPC의 RD는 65000:3
```

**[정답]**:
```json
{
  "VRF_AI": "65000:1",
  "VRF_BIO": "65000:2",
  "VRF_HPC": "65000:3"
}
```

### 📌 Q14. "{host} 장비의 BGP Local-AS 번호는?"

**[정보 분류]**: Routing Inventory (BGP 도메인)

**[찾는 방법]**:
`router bgp` 뒤의 숫자를 찾습니다.

**[PE1.cfg]**:
```properties
router bgp 65000
 bgp log-neighbor-changes
 neighbor 10.255.0.12 remote-as 65000
```

**[정답]**: **65000**

**[의미]**: PE1은 **AS 65000**에 속합니다. (Private AS 범위 64512~65535)

---

### 📌 Q15. "{host} 장비의 BGP 피어(Neighbor) 목록은?"

**[찾는 방법]**:
`neighbor <IP> remote-as <ASN>` 패턴의 모든 라인을 찾습니다.

**[PE1.cfg]**:
```properties
router bgp 65000
 neighbor 10.255.0.12 remote-as 65000
 !
 address-family vpnv4
  neighbor 10.255.0.12 activate
```

**[추출 방법]**:
*   BGP 피어 IP: `10.255.0.12`
*   피어의 AS: `65000` (= 로컬 AS와 같음 → iBGP)

**[정답]**: **['10.255.0.12']**

---

### 📌 Q16. "{host} 장비의 iBGP vs eBGP 피어 분류"

**[iBGP/eBGP 판단]**:
*   로컬 AS = `65000`
*   피어1: `10.255.0.12` (remote-as 65000) → **iBGP** (같은 AS)

**[정답]**:
```json
{
  "ibgp_neighbors": ["10.255.0.12"],
  "ebgp_neighbors": []
}
```

---

### 📌 Q17. "{host} 장비의 {vrf} VRF에 바인딩된 인터페이스는 몇 개?"

**예시**: "PE1의 VRF_AI에 바인딩된 인터페이스는?"

**[찾는 방법]**:
모든 `interface` 설정에서 `vrf forwarding VRF_AI`를 찾습니다.

**[PE1.cfg]**:
```properties

 vrf forwarding VRF_AI        ← VRF_AI에 바인딩!
 ip address 172.16.1.1 255.255.255.0
```

**[정답]**: **1개** (Gi0/1만 VRF_AI에 속함)

**[전체 정리]**:
```json
{
  "VRF_AI": 1,      (Gi0/1)
  "VRF_BIO": 1,     (Gi0/2)
  "VRF_HPC": 0      (어떤 인터페이스도 할당 안됨)
}
```

## 9. 흔한 실수와 해결법

### ❌ 실수 1: Router-ID를 인터페이스로 착각하기

**[잘못된 예]**:
Q: "PE1의 OSPF Area 0 인터페이스 목록?"
A: "Loopback0, 10.255.0.11" ← **틀림!**

**[설명]**:
```properties
router ospf 1
 router-id 10.255.0.11       ← 이것은 라우터의 "이름표"일 뿐!
 network 10.0.1.0 ... area 0
```

**[올바른 답]**:
"Loopback0, GigabitEthernet0/0" (인터페이스 이름만!)

---

### ❌ 실수 2: VRF 인터페이스를 일반 OSPF에 포함시키기

**[잘못된 예]**:
Q: "PE1의 OSPF Area 0 인터페이스?"
A: "Loopback0, Gi0/0, Gi0/1, Gi0/2, Gi0/3" ← **틀림!**

**[설명]**:
```properties
interface GigabitEthernet0/1
 vrf forwarding VRF_AI        ← 이 인터페이스는 VRF_AI의 세계에만 속함!
 ip address 172.16.1.1
```

Gi0/1, Gi0/2는 VRF에 속하므로, 일반 OSPF 설정에는 참여할 수 없습니다.

**[올바른 답]**:
"Loopback0, GigabitEthernet0/0" (VRF 없는 것만!)

---

### ❌ 실수 3: 와일드카드 마스크 계산 실수

**[잘못된 예]**:
`10.255.0.0 0.0.0.255`의 범위?
A: "10.255.0.0 ~ 10.255.0.0" ← **틀림!**

**[올바른 계산]**:
```
IP:       10.255.0.0
Wildcard: 0.0.0.255   (마지막 자리는 아무거나!)
범위:    10.255.0.0 ~ 10.255.0.255
```

---

### ❌ 실수 4: 중복 제거를 안 하기

**[잘못된 예]**:
Q: "PE1의 OSPF Area 0 인터페이스 목록?"
A: "Loopback0, Loopback0, Gi0/0" ← **틀림! (중복)**

**[설명]**:
Loopback0이 `network 10.255.0.11 0.0.0.0`과 `network 10.255.0.0 0.0.0.255` 모두에 포함되지만, 인터페이스는 하나입니다.

**[올바른 답]**:
"Loopback0, GigabitEthernet0/0" (중복 제거!)

---

### ❌ 실수 5: 인터페이스 이름 오타

**[잘못된 예]**:
A: "Gigabitethernet0/0" (소문자) ← **틀림!**
A: "Gig0/0" (약자) ← **틀림!**

**[올바른 표기]**:
A: "GigabitEthernet0/0" (정확한 대소문자)
또는 "Gi0/0" (공식 약자)

## 📚 용어 정리

| 용어 | 의미 | 예시 |
|:---|:---|:---|
| **Hostname** | 장비의 이름 | PE1, P1, Leaf1 |
| **Interface** | 네트워크 연결 포트 | GigabitEthernet0/0 |
| **IP Address** | 네트워크상의 주소 | 10.0.1.1 |
| **OSPF** | 내부 라우팅 프로토콜 | 같은 회사 네트워크용 |
| **BGP** | 외부 라우팅 프로토콜 | 다른 회사와 통신용 |
| **VRF** | 가상 라우팅 공간 | 고객사별 네트워크 분리 |
| **Area** | OSPF의 영역 | Area 0, Area 1 |
| **AS** | Autonomous System | 자치 시스템 번호 |
| **Neighbor** | BGP 피어 | 라우팅 정보 교환 대상 |
| **Wildcard Mask** | 범위 지정용 마스크 | 0.0.0.255 |
| **RD** | Route Distinguisher | VRF 고유 ID (65000:1) |
| **Router-ID** | 라우터 식별자 | 10.255.0.11 |

---

*이 문서는 PE1.cfg를 상세히 분석합니다. PE2, P1, Leaf 등 다른 장비도 동일한 방식으로 읽을 수 있습니다.*
