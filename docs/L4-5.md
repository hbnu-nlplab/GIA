# L4/L5 문제 정의 및 Batfish 구현 가이드

## 개요

이 문서는 네트워크 엔지니어링 Q&A 데이터셋 생성을 위한 L4(네트워크 도달성) 및 L5(What-If/Differential 분석) 레벨 문제의 정의와 Batfish를 활용한 구현 방법을 설명합니다.

**최종 업데이트**: 2025-12-19

---

## 레벨 정의

### L4: 네트워크 흐름 도달성 (Network Flow Reachability)

특정 트래픽이 네트워크를 통해 목적지에 도달할 수 있는지 분석하는 문제입니다. ACL, 방화벽, 라우팅 정책 등의 영향을 고려합니다.

### L5: What-If / Differential 분석 (What-If/Differential Analysis)

네트워크 변경 시나리오(링크 장애, 설정 변경 등)의 영향을 분석하고, 변경 전후의 차이를 비교하는 문제입니다.

## 고급 질문 제안 (LLM 추론 요구)

현재 질문들은 대부분 **단순 조회/검증** 형태입니다. LLM의 **추론 능력**을 평가하려면 아래와 같은 고급 질문을 추가해야 합니다.

### 1. 근본 원인 분석 (Root Cause Analysis) - L5

**현업 시나리오**: "고객이 인터넷 접속이 안 된다고 신고했습니다."

```
[질문]
Host_A에서 Internet_Gateway로의 트래픽이 차단되고 있습니다.
다음 정보를 바탕으로 근본 원인을 추론하세요:
- 경로: Host_A → SW1 → R1 → FW1 → R2 → IGW
- FW1의 ACL 'OUTBOUND_POLICY'에서 차단됨
- 차단된 규칙: "deny tcp any host 203.0.113.0/24 eq 443"

[답변 형식]
{"root_cause": "...", "affected_services": [...], "remediation": "..."}
```

**구현**: `root_cause_analysis` 메트릭 추가 필요

---

### 2. 장애 영향 범위 추정 (Blast Radius Estimation) - L5

**현업 시나리오**: "Spine1 스위치를 재부팅하면 몇 대의 서버에 영향이 가나요?"

```
[질문]
Spine1 장비가 다운될 경우, 영향을 받는 Leaf 스위치와 그에 연결된 호스트 수를 추정하세요.
[답변 형식]
{"affected_leafs": [...], "affected_hosts_count": N, "severity": "HIGH/MEDIUM/LOW"}
```

**구현**: `blast_radius_estimation` 메트릭 추가 필요 (토폴로지 그래프 분석 기반)

---

### 3. 최적 경로 추론 (Optimal Path Reasoning) - L4

**현업 시나리오**: "QoS 정책을 고려할 때, VoIP 트래픽은 어느 경로를 타야 하나요?"

```
[질문]
VoIP 트래픽(UDP, port 5060)이 Host_A에서 SIP_Server로 가는 경우,
DSCP EF 마킹이 적용된 최적 경로를 추론하세요.
단, 다음 조건을 고려해야 합니다:
- R1-R2 링크: 대역폭 1Gbps, 지연 10ms
- R1-R3-R2 링크: 대역폭 10Gbps, 지연 2ms
- QoS 정책: EF 트래픽은 저지연 경로 우선

[답변 형식]
{"recommended_path": [...], "reason": "..."}
```

**구현**: `qos_aware_path_analysis` 메트릭 추가 필요 (인터페이스 대역폭/QoS 정책 파싱)

---

### 4. 설정 오류 탐지 (Misconfiguration Detection) - L4

**현업 시나리오**: "OSPF 네이버가 올라오지 않는 이유가 뭘까요?"

```
[질문]
R1과 R2 사이에 OSPF 네이버가 형성되지 않습니다.
다음 설정을 분석하고 가능한 원인을 모두 나열하세요:

R1:
  interface GigabitEthernet0/0
    ip address 10.0.0.1 255.255.255.0
    ip ospf 1 area 0
    ip ospf hello-interval 10
    ip ospf dead-interval 40

R2:
  interface GigabitEthernet0/0
    ip address 10.0.0.2 255.255.255.252  # 서브넷 불일치!
    ip ospf 1 area 1                      # Area 불일치!
    ip ospf hello-interval 30              # Hello 불일치!

[답변 형식]
{"issues": ["subnet_mismatch", "area_mismatch", "hello_interval_mismatch"], "recommendation": "..."}
```

**구현**: `ospf_compatibility_check` 메트릭 추가 필요 (파라미터 비교 로직)

---

### 5. 복합 장애 시나리오 (Multi-Failure Scenario) - L5

**현업 시나리오**: "동시에 2개 링크가 다운되면 어떻게 되나요?"

```
[질문]
Spine1-Leaf1 링크와 Spine2-Leaf2 링크가 동시에 다운될 경우,
Leaf1에서 Leaf2로의 트래픽 경로가 어떻게 변경되는지 분석하세요.
만약 대체 경로가 없다면 "ISOLATED"라고 답하세요.

[답변 형식]
{"new_path": [...] or "ISOLATED", "path_length_change": N}
```

**구현**: `multi_link_failure_analysis` 메트릭 추가 필요 (조합론 기반 시뮬레이션)

---

### 6. 보안 정책 위반 탐지 (Security Policy Violation) - L4

**현업 시나리오**: "DB 서버에 직접 접근하는 경로가 있나요?"

```
[질문]
네트워크 정책: "모든 DB 트래픽(TCP 3306)은 반드시 WAF를 경유해야 한다."

다음 토폴로지에서 정책을 우회하는 경로가 존재하는지 확인하세요:
- App_Server (10.0.1.10) -> DB_Server (10.0.2.20)
- WAF 위치: FW1

[답변 형식]
{"violation_exists": true/false, "bypass_path": [...] or null}
```

**구현**: `security_policy_bypass_check` 메트릭 추가 필요 (Waypoint 검증 확장)

---

### 7. 용량 병목 분석 (Capacity Bottleneck Analysis) - L5

**현업 시나리오**: "트래픽 폭증 시 병목 구간은 어디인가요?"

```
[질문]
현재 네트워크에서 Leaf 스위치들이 Spine으로 보내는 트래픽이 2배 증가할 경우,
가장 먼저 과부하가 걸릴 것으로 예상되는 링크는 어디입니까?
(각 링크의 현재 활용률과 대역폭 정보가 주어집니다.)

[답변 형식]
{"bottleneck_link": "Spine1-Leaf3", "current_utilization": "80%", "projected_utilization": "160%"}
```

**구현**: 인터페이스 대역폭 + 트래픽 시뮬레이션 필요 (Batfish 외 추가 데이터 필요)

## 기존 Batfish API 매핑 표

| 문제 유형       | Batfish Query                | 주요 파라미터                    | 반환 데이터         |
| --------------- | ---------------------------- | -------------------------------- | ------------------- |
| 기본 도달성     | `reachability()`             | `headers`, `pathConstraints`     | Flow, Traces        |
| 경로 추적       | `traceroute()`               | `startLocation`, `headers`       | Traces, Hops        |
| 차이 분석       | `differentialReachability()` | `snapshot`, `reference_snapshot` | Flow differences    |
| OSPF 분석       | `ospfEdges()`                | `nodes`                          | OSPF neighbor edges |
| 인터페이스 속성 | `interfaceProperties()`      | `nodes`                          | Interface details   |
