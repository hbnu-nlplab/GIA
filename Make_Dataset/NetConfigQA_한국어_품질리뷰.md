## 2. 한국어가 영어보다 잘 된 부분 (👍)

영어에서 문제로 지적한 항목들이 한국어에서는 대부분 해결되어 있습니다:

### ✅ Root Cause Analysis → 자연스러운 한국어

| 영어 (문제) | 한국어 (양호) |
|------------|-------------|
| `What is the root cause analysis from leaf4 to p4?` | `leaf4에서 p4로의 통신이 실패할 때, 어느 장비에서 차단됩니까?` |

한국어는 "통신 실패 시 차단 장비"라는 맥락을 명확히 제공합니다.

### ✅ Worst Case → 구체적 질문

| 영어 (모호) | 한국어 (명확) |
|------------|-------------|
| `What is the worst case failure analysis?` | `단일 장비 장애 시 가장 큰 영향을 주는 장비는?` |

### ✅ Loop Detection → 자연스러운 질문

| 영어 (어색) | 한국어 (자연) |
|------------|-------------|
| `What is the loop detection?` | `네트워크에 포워딩 루프가 존재합니까?` |

### ✅ Multi-link Failure → 시나리오 서술

| 영어 (직역) | 한국어 (서술적) |
|------------|-------------|
| `What is the multi link failure reachability from leaf4 to p3, when links leaf1-pe1 and leaf2-leaf3 fail?` | `(시나리오) 'leaf1-pe1' 링크와 'leaf2-leaf3' 링크가 동시에 다운되었습니다. 이 상황에서 'leaf4'에서 'p3'로의 트래픽 전달이 가능합니까?` |

### ✅ Asymmetric Path → 명확한 요청

| 영어 (모호) | 한국어 (명확) |
|------------|-------------|
| `What is the asymmetric path comparison between pe2 and pe1?` | `pe2과 pe1 사이의 Forward/Reverse 경로를 비교해주세요.` |

### ✅ 답변 형식 힌트가 훨씬 상세

```
영어: [Answer format: plain string]
한국어: [답변 형식: '가능 (대체경로: A→B→C)' 또는 '불가능 (원인: 장비명에서 사유)']
```

```
영어: [Answer format: plain string]  
한국어: [답변 형식: '예, 완전 분리' 또는 '아니오, N개 흐름만 영향']
```

이렇게 예시까지 제공하는 것은 LLM 평가 시 매우 유리합니다.

## 3. 한국어 데이터셋의 문제점

### 🔴 Issue 1: 답변 언어 불일치 — 가장 심각 (128건)

한국어 질문에 영어 답변이 그대로 들어 있습니다:

```
Q: 네트워크에 포워딩 루프가 존재합니까? [답변 형식: '없음' 또는 '발견: A→B→C→A']
A: "NONE"                          ← 힌트는 '없음'인데 답변은 "NONE"

Q: leaf4에서 p4로의 통신이 실패할 때, 어느 장비에서 차단됩니까?
A: "pe2"                           ← 이건 OK (장비명이라 언어 무관)

Q: 172.16.4.2에서 172.16.3.2로 트래픽이 차단된다면 차단 지점을 알려주세요.
A: "ALLOWED"                       ← 힌트는 '허용'인데 답변은 "ALLOWED"

Q: pe2과 pe1 사이의 Forward/Reverse 경로를 비교해주세요.
A: "Forward: pe2 -> p3 -> p2 -> pe1, Reverse: ..."   ← 전부 영어

Q: 설정 변경 후 leaf1에서 p3까지의 경로/도달성 변경 여부를 알려주세요.
A: "CHANGED (25 entries: ...)"     ← 힌트는 한국어, 답변은 영어

Q: 'leaf1', 'leaf2', 'leaf3'가 동시에 다운되면 네트워크가 완전히 분리됩니까? 
   [답변 형식: '예, 완전 분리' 또는 '아니오, N개 흐름만 영향']
A: "NO (affected_flows: 15)"       ← '아니오'가 아닌 "NO"
```

**영향**: LLM 평가 시 정답 채점이 매우 어려워집니다. LLM이 한국어로 "허용", "없음", "아니오"라고 답하면 정답인데, ground truth가 "ALLOWED", "NONE", "NO"이므로 exact match 실패.

**개선 방안**:
- **방안 A (권장)**: 답변도 한국어로 변환 — `"NONE"→"없음"`, `"ALLOWED"→"허용"`, `"NO"→"아니오"`, `"DISCONNECTED"→"불가능"`, `"REROUTED"→"가능"`, `"CHANGED"→"변경됨"` 등
- **방안 B**: 질문의 답변 형식 힌트를 영어로 통일 — 하지만 이러면 한국어 질문의 자연스러움이 떨어짐
- **방안 C**: 채점 시 동의어 매핑 테이블 사용 — `{"NONE": "없음", "ALLOWED": "허용", ...}`

### 🔴 Issue 2: 답변 형식 힌트와 실제 답변 불일치 (~50건)

질문에서 한국어 답변 형식을 안내하지만 실제 답변은 영어 형식:

```
힌트: '예, 완전 분리' 또는 '아니오, N개 흐름만 영향'
답변: "NO (affected_flows: 15)"

힌트: '가능 (대체경로: A→B→C)' 또는 '불가능 (원인: 장비명에서 사유)'
답변: "DISCONNECTED (reason: NO_ROUTE at pe2)"
답변: "REROUTED (path: p1 -> p2 -> p3)"
```

LLM이 힌트를 따라 `"불가능 (원인: pe2에서 NO_ROUTE)"`라고 답하면 의미상 정확하지만 채점에서 불일치 처리될 수 있습니다.

### 🟡 Issue 3: 조사 '과/와' 일괄 '과' 사용 (78건)

영어 장비명 뒤 조사가 모두 '과'로 통일되어 있습니다:

```
leaf2과 leaf3  → leaf2와 leaf3 (이→와)
pe2과 pe1     → pe2와 pe1 (이→와)
p4과 pe1      → p4와 pe1 (사→와)
```

엄밀히 말하면 영어 장비명/숫자 뒤 조사 규칙은 논란이 있지만, 일반적으로:
- 1(일), 3(삼), 6(육), 7(칠), 8(팔), 0(영/공) → 받침 있음 → **과**
- 2(이), 4(사), 5(오), 9(구) → 받침 없음 → **와**

따라서 `leaf2과` → `leaf2와`, `leaf4과` → `leaf4와`, `pe2과` → `pe2와`로 수정이 필요합니다.

### 🟡 Issue 4: "AS None" 표기 (20건)

```
Q: leaf2과 p3의 BGP Local AS 번호를 각각 알려주세요.
A: "leaf2: AS None, p3: AS None"
```

"AS None"은 Python의 `None` 값이 그대로 문자열화된 것입니다. 한국어 맥락에서는 `"설정되지 않음"` 또는 `"미설정"`, 혹은 최소한 `"N/A"`가 더 적절합니다.

### 🟢 Issue 5: 일부 영어 용어 혼재

대부분의 질문은 자연스럽지만, 일부에서 영어 기술 용어가 불필요하게 섞여 있습니다:

```
"Password Encryption 기능 설정값"  → "패스워드 암호화 설정" 또는 그대로 OK
"OSPF Backbone Area(Area 0)"     → 이건 표준 용어라 OK
"Forward/Reverse 경로"            → 이것도 업계 관행상 OK
```

이 부분은 네트워크 분야 특성상 영어 용어를 그대로 쓰는 것이 오히려 자연스러울 수 있어서, 큰 문제는 아닙니다.

## 5. LLM 답변 가능성 평가

Config를 context로 제공하는 경우:

| Level | LLM 답변 가능성 | 한국어 특이사항 |
|-------|:---:|------|
| **L1** | 🟢 높음 | 질문이 명확하여 답변 용이 |
| **L2** | 🟢 높음 | 답변 형식 힌트가 도움됨 |
| **L3** | 🟡 중간 | 답변 형식은 잘 안내되나, LLM이 한국어/영어 중 어떤 걸로 답할지 혼란 |
| **L4** | 🟡 중간 | 시나리오 질문이 자연스러워 이해도는 높지만, 시뮬레이션 필요 |
| **L5** | 🔴 낮음 | 한국어 질문은 우수하나, 답변 형식 불일치가 채점을 어렵게 함 |

**핵심**: 한국어 데이터셋은 질문 품질 자체는 영어보다 우수하지만, **답변이 영어로 남아 있어서 실제 LLM 평가 파이프라인에서 채점 정확도가 떨어질 위험**이 큽니다.
